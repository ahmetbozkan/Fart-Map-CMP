# EPIC-01-01: Bootstrap and Walking Skeleton

## Status
- Workflow state: Active
- Owner: lead implementation agent
- Parent phase: PHASE-01

## Epic Intent
- Objective: a new Compose Multiplatform repository that builds, tests and runs on Android and iOS, with the architecture skeleton, backend scaffold, CI and secrets hygiene in place, so every later epic adds features instead of infrastructure.
- Target user outcome: none directly; it is the foundation that makes the under-60-seconds first log possible.
- Why this is grouped as one epic: all items are cross-cutting infrastructure that must exist before any feature story can pass the Definition of Ready.

## Scope
- In scope: repository layout (`shared` module with `feature/*` and `core/*` packages, `firebaseData` and `umbrella` per ADR-0021, `androidApp`/`iosApp` shells, `backend/`), version catalog baseline and `TechStack.md` §3.1, JDK pin, secrets templates + `.gitignore` from the first commit, GitHub Actions pipeline (shared tests, Android build, iOS framework link + simulator build, functions tests, rules tests), Koin modules, typed navigation shell with the four tabs and the auth entry, theme tokens from `DesignSpecification.md` §3–§7, observability base (typed `AppError`, logger, Crashlytics and Analytics init, event contract), Room database bootstrap with the pending-operations table and a migration test, SyncEngine skeleton, App Check init, Firebase `dev` config injection, backend scaffold with default-deny rules and one smoke function under emulator tests, README with the validation commands.
- Out of scope: any feature behavior (map data, logging, reactions, purchases, ads, push), production Firebase config, store listings.

## Acceptance Boundary
- Epic-level acceptance condition 1: `./gradlew :androidApp:assembleDevDebug :androidApp:assembleProdDebug :shared:allTests :umbrella:linkDebugFrameworkIosSimulatorArm64` and an `xcodebuild` simulator build pass locally and in CI; the iOS app links every Firebase product the shared code references (`TechStack.md` §6.2).
- Epic-level acceptance condition 2: both apps launch to the four-tab shell with placeholder screens; the auth entry shows Google / Apple / Continue without account (non-functional stubs allowed); no file containing a secret or Firebase config is tracked; `firebase deploy --only firestore:rules,functions` works against `dev` from CI.

## Dependencies

## Risks
- Scope risk: gold-plating the skeleton; keep to the acceptance boundary.
- Dependency risk: latest-stable library set may not be mutually compatible on day one; the bootstrap story records the proven set.
- Safety/privacy risk: a config file slipping into the first commit; templates and the ignore rules land before any config is created.

## Planned Stories
- STORY-01-01-01: Project bootstrap and build pipeline (Review since 2026-10-21: implemented and validated locally on both platforms and the backend emulator; CI run pending the owner's first push)
- STORY-01-01-02: Core packages — DI, navigation shell, theme, observability base
- STORY-01-01-03: Persistence and sync skeleton — Room, pending operations, SyncEngine tick
- STORY-01-01-04: Backend scaffold — default-deny rules, functions project, emulator tests, CI deploy to `dev`
