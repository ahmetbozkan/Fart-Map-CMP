# TASK-01-01-01-01: Project identity and environment model (dev / prod)

## Status
- Type: chore
- Priority: P1
- Workflow state: Review
- Owner: lead implementation agent
- Parent story: STORY-01-01-01

## Intent
- Objective: make the template project carry the product's identity and a two-environment model on both platforms, so every later build knows which Firebase project it talks to.
- Expected outcome: `devDebug`/`devRelease`/`prodDebug`/`prodRelease` on Android and `Debug-dev`/`Release-dev`/`Debug-prod`/`Release-prod` on iOS, each wired to its Firebase app; one shared `AppEnvironment` value in Kotlin.

## Traceability
- Feature/system link: foundation for `MAP-01`, `CREATE-01`
- Loop link: enables L1
- Pillar link: Location (map host)
- Architecture contracts touched: `FirebaseStrategy.md` §8, `SecurityAndSecrets.md` §4, `MultiplatformStrategy.md` §6, `Architecture.md` §6
- ADR links (if applicable): ADR-0003, ADR-0008, ADR-0015

## Scope
- In scope: Android `env` flavor dimension (`dev` with `applicationIdSuffix ".dev"` and name suffix, `prod`); `google-services.json` moved to `androidApp/src/dev/` and `androidApp/src/prod/` (untracked); Google Services plugin; iOS build configurations and xcconfig files (`Dev.xcconfig`, `Prod.xcconfig` setting `PRODUCT_BUNDLE_IDENTIFIER` = `com.ahmetbozkan.fartmap[.dev]`, display name, `APP_ENV`); run-script phase copying `GoogleService-Info-<env>.plist` into the bundle; two shared schemes `FartMap Dev` / `FartMap Prod`; `AppEnvironment` (`DEV`/`PROD`, Firebase project id, flags) as `expect`/`actual` fed from `BuildConfig` and `Info.plist`; Kotlin package root fixed to `com.ahmetbozkan.fartmap` (matches the registered app ids); module naming kept as `shared` + `androidApp` + `iosApp`.
- Out of scope: Firebase SDK calls, App Check providers (STORY-01-01-02), signing.

## Implementation Plan
1. Add flavors and `applicationIdSuffix` to `androidApp/build.gradle.kts`; add the Google Services plugin to the catalog and module; move the two JSON files under `src/<flavor>/`.
2. Create `iosApp/Configuration/Dev.xcconfig` and `Prod.xcconfig` including `Config.xcconfig`; add the four configurations to the project; map two shared schemes; set bundle ids and `APP_ENV`.
3. Add the plist-copy run-script phase (reads `APP_ENV`, copies the matching plist as `GoogleService-Info.plist`, fails the build if missing).
4. Pass `APP_ENV` to the Gradle embed phase so the right framework variant is embedded.
5. Implement `AppEnvironment` in `core/platform` with Android (`BuildConfig`) and iOS (`Info.plist` key) actuals; expose through Koin later (STORY-01-01-02).
6. Update `Architecture.md` §6 wording (`com.ahmetbozkan.fartmap`, module `shared`) and record the identifiers in `TechStack.md` §3.1 notes.

## Risks
- Security/privacy: a plist or JSON landing in git → TASK-03 ignore rules land first; verify with `git ls-files`.
- Correctness/regression: wrong flavor picking the wrong Firebase project → `AppEnvironment` logs the project id at startup in debug builds.
- Platform parity: iOS configuration drift between Debug and Release variants → xcconfig inheritance, one source per env.
