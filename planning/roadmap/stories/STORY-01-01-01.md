## Scope
- In scope: create the project from the current Kotlin Multiplatform template with the owner's identifiers; version catalog on the latest stable compatible set, proven by building both targets; record the baseline in `TechStack.md` §3.1; `.gitignore` and committed templates (`google-services.json.template`, `GoogleService-Info.plist.template`, `local.properties.example`); README with JDK, commands and config injection steps; iOS app target linking all referenced Firebase products via SPM; shared-test configuration that does not require Firebase; GitHub Actions workflow running the validation set; `backend/` folder with `firebase.json`, `.firebaserc` (`dev` default), default-deny `firestore.rules`, empty indexes, functions project with one smoke function and an emulator test.
- Out of scope: feature code, Koin modules and navigation shell (STORY-01-01-02), Room (STORY-01-01-03), real rules (STORY-01-01-04).

## Acceptance Criteria (Given/When/Then)
1. Given a clean clone and the documented JDK, when `./gradlew :composeApp:assembleDebug :composeApp:testDebugUnitTest :composeApp:linkDebugFrameworkIosSimulatorArm64` runs, then all three pass.
2. Given the documented `xcodebuild` command for the iPhone simulator, when it runs after the Firebase config is injected locally, then the app builds and launches to a placeholder screen.
3. Given the repository history, when `git log -p` is searched for API keys, `google-services.json` or `GoogleService-Info.plist`, then no tracked secret or config file exists in any commit.
4. Given a pull request, when CI runs, then the Android build, shared tests, iOS build, functions tests and rules tests report status within one workflow.
5. Given `TechStack.md` §3.1, when the story is done, then every row carries the proven version and the date.
