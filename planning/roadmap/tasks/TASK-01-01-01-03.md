# TASK-01-01-01-03: Secrets and config hygiene

## Status
- Type: chore
- Priority: P0
- Workflow state: Review
- Owner: lead implementation agent

## Intent
- Objective: make it structurally impossible to commit Firebase configs, keys or signing material, and make injection repeatable for a developer and for CI.
- Expected outcome: ignore rules, committed templates, an injection script, a CI secret scan, and documentation; `git ls-files` never lists a real config.

## Scope
- In scope: `.gitignore` rules (added 2026-10-18 when the four configs were found staged and were unstaged); templates `androidApp/src/dev/google-services.json.template`, `androidApp/src/prod/google-services.json.template`, `iosApp/Configuration/GoogleService-Info-dev.plist.template`, `…-prod.plist.template` with placeholder values; `scripts/inject-config.sh` that writes the real files from environment variables (base64) for CI and from a local `~/.fartmap/` folder for developers; `local.properties.example`; README section "Config injection"; a pre-commit hook suggestion (optional, documented) and a CI job running a secret scan (gitleaks) on every PR; Maps key via `BuildConfig`/xcconfig from untracked properties, never a manifest literal.
- Out of scope: signing keys for release (later), Play App Signing.

## Implementation Plan
1. Verify the ignore rules cover every config path used by TASK-01; add the templates.
2. Write `scripts/inject-config.sh`; document the variables: `GOOGLE_SERVICES_JSON_DEV`, `GOOGLE_SERVICES_JSON_PROD`, `GOOGLE_SERVICE_INFO_PLIST_DEV`, `GOOGLE_SERVICE_INFO_PLIST_PROD` (base64), `MAPS_API_KEY_DEV`, `MAPS_API_KEY_PROD`.
3. Add the gitleaks job to CI (TASK-05 wires it) and a repository scan of history once.
4. README: injection steps, never-commit rule, what to do if a config was committed.
