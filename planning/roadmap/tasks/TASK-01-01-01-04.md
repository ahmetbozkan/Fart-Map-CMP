# TASK-01-01-01-04: iOS Firebase linking and shared-test isolation

## Status
- Type: chore
- Priority: P1
- Workflow state: Review
- Owner: lead implementation agent
- Parent story: STORY-01-01-01

## Intent
- Objective: prevent the PoC's `framework 'FirebaseCore' not found` failure by wiring Firebase on iOS correctly from the start and keeping shared tests free of Firebase.
- Expected outcome: the iOS app links every Firebase product the shared code will reference; `:shared:iosSimulatorArm64Test` runs without Firebase; the Xcode build runs from the command line on both schemes.

- Feature/system link: foundation

## Scope
- In scope: SPM products on the `iosApp` target — FirebaseCore, FirebaseAuth, FirebaseFirestore, FirebaseStorage, FirebaseAnalytics, FirebaseCrashlytics, FirebaseMessaging, FirebaseAppCheck (the set ADR-0015 names; already partially resolved in `Package.resolved`); `FirebaseApp.configure()` in an `AppDelegate` after the plist copy; the Kotlin framework embed phase; a `linkerOpts`/`-framework` review so the static framework's auto-links resolve; a `Firebase-free` rule for `commonTest`/`iosTest` (Firebase types only behind repository interfaces in `core/data`, fakes in tests); an `xcodebuild` command documented in the README; the Crashlytics `run` upload script phase (dSYM) prepared but disabled until Crashlytics is initialized.
- Out of scope: any Firebase feature usage.

## Implementation Plan
1. Add the SPM products to the target; confirm `Package.resolved` is tracked under `xcshareddata`.
2. Add `AppDelegate` with `FirebaseApp.configure()`; keep `iOSApp.swift` as the entry.
3. Add a tiny shared `expect fun platformName()` style smoke that references nothing from Firebase, and a GitLive import behind an interface to prove the link path once GitLive enters the catalog (TASK-02).
4. Run `xcodebuild -scheme "FartMap Dev" -destination 'platform=iOS Simulator,name=iPhone 17' build` and the Kotlin test task; fix link flags.
5. Document both commands in the README.
