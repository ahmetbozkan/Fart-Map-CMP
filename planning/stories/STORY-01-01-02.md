# STORY-01-01-02: Core packages (DI, navigation shell, theme, observability, StateViewModel)

Status: Review   Epic: EPIC-01-01   Features: foundation for MAP-01, PROFILE, SOCIAL, RANK tabs   ADRs: ADR-0003, ADR-0004, ADR-0005, ADR-0008, ADR-0015, ADR-0018, ADR-0020

## Goal
Both apps launch through a stub auth entry into the four-tab, map-first shell, themed from the design tokens. The shared base the features build on exists: Koin, typed routes, `StateViewModel`, `AppError`/`AppResult`, logger, Crashlytics and Analytics. The `new-feature` templates compile against it.

## Scope
- **In:**
  - `core/di`: `sharedModules` + `firebaseDataModules` + a platform module, composed at startup in the Android `Application` and in `umbrella` for iOS.
  - `core/presentation`: `StateViewModel<S, A, E>(initial)` exactly as the template documents it (`state: StateFlow`, `events: Flow` from a buffered `Channel`, `onAction`, `setState`, `sendEvent`).
  - `core/observability`:
    - `AppError` with the Observability.md §4 categories;
    - `AppResult<T>` (`Success` / `Failure`);
    - `Throwable.toAppError()`, which rethrows `CancellationException`;
    - a `Logger` contract with the §5 fields and redaction at source;
    - an `AnalyticsEvent` contract with only `app_open` for now.
  - `firebaseData`: Crashlytics and Analytics adapters behind those contracts. The Crashlytics Gradle plugin on Android. Collection is off in `dev` builds and on in `prod`.
  - `core/navigation`:
    - `@Serializable` routes: `Splash`, `Auth`, `Main` with tabs `Map` / `Social` / `Rank` / `Profile`;
    - a `SessionState` (`Loading` / `SignedOut` / `Active(anonymous | linked)`) that picks the start destination;
    - a navigator that clears the auth graph on success and the protected graphs on sign-out.
  - **The stub session:** an in-memory `SessionRepository` that starts `SignedOut`. On the auth entry, Google and Apple are visible but disabled ("coming soon"). "Continue without account" moves the session to `Active(anonymous)`. The real providers come in EPIC-01-02.
  - `core/design`:
    - `FartMapTheme` (light and dark) from DesignSpecification §3–§7: colors, semantic colors, type scale, spacing, shapes, elevation;
    - the minimal shared components the templates use: `LoadingState`, `ErrorState`, `EmptyState`, and a snackbar host.
  - **Placeholder tab screens** with product-voice copy in string resources. Map stays the default tab.
  - **Housekeeping:**
    - refresh `STATE.md`;
    - bump the CI actions off Node 20;
    - fix the doc naming to `AppResult` (Architecture.md §5 and Observability.md §4 say `Result<T>`; the templates and LocalData.md say `AppResult`).
- **Out:**
  - real auth, age gate and account linking (EPIC-01-02);
  - the map SDK and markers (EPIC-01-03);
  - the Log modal;
  - Remote Config, `AppWriteScope` and persistence (STORY-01-01-03);
  - consent UI (UMP/ATT, EPIC-01-06);
  - bundled Inter / JetBrains Mono fonts. These are a follow-up task: they are downloaded files under the OFL licence, so the owner adds them or approves the download. Until then the theme uses the platform default family with the DS type scale.

## Acceptance
1. Given a fresh install, when the app launches on Android or iOS, then the splash resolves to the auth entry. Its "Continue without account" opens the shell on the **Map** tab, and Back does not return to the auth entry.
2. Given the shell, when the user taps Social, Rank or Profile, then that placeholder shows with the filled active icon. Switching tabs keeps each tab's back stack.
3. Given system dark mode, when the app is open, then the dark palette from DS §3 applies. Given light mode, the light palette applies.
4. Given `SessionState` values, when mapped, then `Loading` → Splash, `SignedOut` → Auth and `Active(anonymous | linked)` → Main. Going from anonymous to linked keeps the back stack, and sign-out clears it back to Auth. These are unit tests.
5. Given each route, when it is serialized and decoded, then it round-trips. An invalid argument falls back safely; this is a unit test.
6. Given a test `StateViewModel`, when an action updates state and sends an event, then `state` reflects it and the event is delivered once. This is a unit test.
7. Given a thrown `CancellationException`, `toAppError()` rethrows it, and other throwables map to the right `AppError` category. Given a log call carrying coordinates, a token or an email, the emitted record has them redacted. These are unit tests.
8. Given a `dev` build, Crashlytics and Analytics collection is disabled. Given a `prod` build, it is enabled and `app_open` is logged. This is checked by build config and a manual run.
9. The `new-feature` templates, copied into a scratch feature, compile and their ViewModel test passes. The scratch feature is not committed.
10. `scripts/verify.sh --full` is green, and CI's Android, iOS, shared tests and backend jobs are green on the PR.
