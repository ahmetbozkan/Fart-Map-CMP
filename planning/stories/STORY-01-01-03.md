# STORY-01-01-03: Local data layer (Firestore persistence, write pattern, preferences, Remote Config contract)

Status: Review   Epic: EPIC-01-01   Features: foundation for CREATE-01/03, MAP-01, MON-01/03   ADRs: ADR-0022, ADR-0023, ADR-0024, ADR-0019

## Goal
The plumbing every data feature uses exists and is tested, so EPIC-01-03/04 only add repositories:
- Firestore runs with a persistent cache.
- Writes go through one fire-and-forget path that reports rejections.
- Sign-out wipes local data.
- Preferences live in DataStore, and runtime levers come from a typed `RemoteConfig` contract with safe defaults.

No user-visible change except `app_open` now carrying `is_first_open`.

## Scope
- **In:**
  - **Firestore setup (`firebaseData`).** Persistent cache of 200 MB, applied once at startup before any Firestore call: Android `FartMapApplication`, iOS umbrella `startApp`. Repositories get Firestore through a `FirestoreProvider` that always returns the current instance; they never hold one across a sign-out (GitLive re-fetches the platform instance, and after `terminate()` it is a new one with default settings).
  - **The write path (LocalData.md §3):**
    - `AppWriteScope` (`launchWrite(op) { … }`) and `PendingWriteMonitor` (`rejections: Flow<WriteRejected>`). Contracts go in `core/domain`, so ViewModels can observe rejections.
    - The implementation lives in `shared`: an app-scoped `SupervisorJob` scope, never awaited by callers. It maps failures through an injected error mapper, logs `write_rejected`, emits the event, ignores cancellation and never retries.
    - `firebaseData` supplies the Firebase-exception → `AppError` mapper (permission denied, invalid argument, unavailable, …).
  - **Preferences (DataStore, LocalData.md §5).** A file per platform (Android `filesDir`, iOS Documents), created through a platform Koin module, which is the first platform module.
    - Typed accessors only for keys used now:
      - the first-open flag, giving `is_first_open` on `app_open`;
      - `last_visibility_mode`, with the ADR-0023 default resolver (unset → PUBLIC for the 18+ band, FOLLOWERS for 13–17 and for an unknown band; last-used wins after that).
    - `VisibilityMode` and `AgeBand` live in `core/domain`. An unknown wire value decodes to PRIVATE.
    - The other §5 keys are added by the features that use them.
  - **Sign-out reset (LocalData.md §7).** A `SignOut` use case:
    1. `SessionRepository.signOut()`;
    2. `LocalDataReset`, which is `terminate()` → `clearPersistence()` → re-apply settings in `firebaseData`;
    3. clearing the user-scoped DataStore keys (the device-scoped first-open flag is kept).

    No UI calls it yet; Settings arrives in EPIC-01-07.
  - **Remote Config contract (ADR-0024).** A `RemoteConfig` interface in `core/platform` with typed keys and safe defaults:
    - the rewarded-ad daily cap is 3 (display-only; the server enforces it);
    - the starter-pack offer is enabled;
    - the offering id is `default`.

    Bound to an in-app-defaults implementation for now.
  - **Docs and templates.** `LocalData.md` gets the provider and reset details. `new-feature` `RepositoryImpl.kt` uses `FirestoreProvider` and compiles against the real `AppWriteScope`.
- **Out:**
  - **The Firebase Remote Config adapter.** It needs the GitLive `firebase-config` artifact plus the `FirebaseRemoteConfig` SPM product linked in Xcode, and TechStack schedules it with its first consumer in EPIC-01-06. Editing the Xcode project blind from Windows is also avoided.
  - Fart, reaction and entitlement repositories (EPIC-01-03/04/06).
  - The sign-out UI and the anonymous sign-out warning (EPIC-01-02/07).
  - Real age-band capture (EPIC-01-02); until then the band is unknown, so the resolver yields FOLLOWERS.

## Acceptance
1. Given app start on Android or iOS, Firestore settings with a persistent 200 MB cache are applied before any Firestore access, exactly once.
2. Given `launchWrite` with a block that never completes, the caller returns immediately and the app keeps running. This is a unit test.
3. Given a launched write that fails with a mapped error, `PendingWriteMonitor` emits `WriteRejected(op, error)` once and a `write_rejected` ERROR log is recorded. A cancelled write emits nothing. These are unit tests.
4. Given the visibility resolver:
   - an unset value gives PUBLIC for ADULT and FOLLOWERS for TEEN or UNKNOWN;
   - after the user picks a value, that value is returned for every band;
   - an unknown stored value reads as PRIVATE.

   These are unit tests with a fake preferences store.
5. Given the first launch, `app_open` carries `is_first_open = true`; on later launches it is `false`. This is a unit test plus a manual check.
6. Given `SignOut`, the session becomes SignedOut, `LocalDataReset` runs once, and the user-scoped keys are cleared while the first-open flag stays. This is a unit test.
7. Given `RemoteConfig`, every key returns its documented default. This is a unit test.
8. `new-feature` templates, including `RepositoryImpl.kt` (copied into a scratch feature in `firebaseData`), compile. The scratch is not committed.
9. `scripts/verify.sh --full` is green, and CI's Android, iOS, shared tests and backend jobs are green on the PR.

- New tests:

  - real DataStore on a temp file: first-open once, visibility round-trip, unknown value → PRIVATE, user-scoped clear keeps device keys;
  - visibility resolver incl. the minor clamp;
  - `SignOut` branches (success, failed session sign-out wipes nothing, failed/throwing wipe still clears keys, clear failure reported);

- Reviews (code + security) fixed:
  - rejections were dropped with no collector (now a buffered channel);
  - writes could reorder (single-lane dispatcher);
  - pending writes now cancelled before the wipe, so no spurious rejections for the next user;
  - reset re-applies settings even after a failed wipe;
  - `SignOut` stops on a failed session sign-out, otherwise always clears user keys (also under cancellation);
  - DataStore errors become safe defaults or typed failures instead of crashing the root;
  - iOS store moved to Application Support;
  - a remembered PUBLIC is never preselected for TEEN/UNKNOWN.
- **Deviations:**
  - The Firebase Remote Config adapter stays in EPIC-01-06 (new artifact + Xcode SPM product); this story ships the contract and defaults.
  - Only the two DataStore keys in use now are implemented; the rest of `LocalData.md` §5 arrives with its features.
  - A failed cache wipe is returned typed but not retried automatically yet (documented in `LocalData.md` §7).
