# STORY-01-01-04: Backend rules skeleton and `runOnce` fix

Status: Todo   Epic: EPIC-01-01   Features: foundation for MAP-01, CREATE-01/03, SOCIAL reactions, safety (report/block), MON-01/03   ADRs: ADR-0015, ADR-0016, ADR-0017, ADR-0018, ADR-0019, ADR-0023

## Goal
Firestore rules enforce the DataContracts §5 intent for every Phase 1 collection, with an emulator test for each allowed and denied case. The feature epics then build clients against real rules instead of default-deny. Triggers become safely idempotent.

## Scope
- **In — rules (`backend/firestore.rules`):**
  - **Shared helpers:** signed in (anonymous counts, ADR-0018), owner, enum and range checks, server-timestamp checks, "only these keys changed".
  - **`farts/{fartId}`:**
    - **create** by the author only:
      - `fart_id`/`author_user_id` match the path and the uid;
      - only schema keys, so no precise `lat`/`lng` on the public doc (ADR-0019);
      - enums and ranges: visibility, flavor 1–5, intensity 0–1, description ≤ 500;
      - counters and moderation fields start at zero/false;
      - server timestamps;
      - `avatar_id`/`sound_id` must be a free catalog item or one granted in `user_entitlements`. This fails closed; the rewarded-token path is added with EPIC-01-06.
    - **update** by the author: description, visibility, `updated_at`, and a soft delete (`is_removed` + reason). Counters and moderation fields are never client-writable.
    - **no hard delete.**
    - **get:** PUBLIC to any signed-in user; FOLLOWERS to the author or an approved follower with no block either way; PRIVATE to the author. Hidden or removed farts are visible only to the author.
    - **list** (queries) is allowed only when the query constrains `visibility_mode == PUBLIC` and not hidden/removed, or `author_user_id == uid`. This fixes the query shape EPIC-01-03 must use for the map.
  - **`farts/{id}/private/location`:** author-only read and write; keys `lat`, `lng`, `updated_at`.
  - **`farts/{id}/reactions/{userId}`:**
    - create/update/delete only as yourself;
    - the type must be one of the five enum values;
    - you must be able to read the fart;
    - readable by anyone who can read the fart.
  - **`blocks/{blockerId_blockedId}`:** create/delete by the blocker only; the id matches the fields; readable by the blocker only.
  - **`moderation_reports/{id}`:** create by the reporter, with status OPEN and server timestamps; no client read or update.
  - **`cosmetic_items`:** read when signed in, never client-written.
  - **`user_entitlements/{uid}`, `rewarded_unlocks/{uid}/tokens`:** owner read; never client-written.
  - **`users/{uid}/devices/{id}`:** owner only.
  - **`users/{uid}`:** see the open question. The proposed default is owner-only read and write for now; create and update are limited to client-editable fields; counters, suspension, age band, anonymity and providers are server-managed.
  - **Still default-deny** (opened by their Phase 2+ stories): comments, `follow_relationships` writes, progression, XP, achievements, challenges, leaderboards. The FOLLOWERS read rule already reads `follow_relationships`; rules lookups don't need read access.
- **In — tests:** `backend/functions/test/emulator/*.rules.test.ts`, one file per area. Each allowed and denied case for owner, other user, anonymous user and signed-out user, plus DataContracts §9 items 1, 3, 6, 7, 8, 9 and 10 as far as Phase 1 collections go.
- **In — idempotency (`backend/functions/src/lib/idempotency.ts`):** `runOnce` claims with status `running` plus a lease, marks `done` after the work, and releases the claim on failure so a redelivery retries. A run whose lease has expired can be re-claimed. Every record gets an `expire_at` with a Firestore TTL field override (`firestore.indexes.json`) so `function_runs` doesn't grow forever. Emulator tests cover:
  - first run;
  - duplicate skipped;
  - failure, then retry runs;
  - expired lease re-claimed;
  - `expire_at` set.
- **In — `onFartCreated`:** the handler is extracted and tested against the emulator. It stays deployed to dev only: the prod deploy in `deploy-backend.yml` names its functions explicitly (`functions:health`), so a new function reaches prod only when it is added on purpose.
- **In — CI and scripts:** the emulator test script runs both rules and idempotency suites.
- **Out:**
  - App Check enforcement (console, EPIC-01-02);
  - the public-coordinate projection function (ADR-0019, EPIC-01-04);
  - the reaction counter trigger (EPIC-01-05);
  - token consumption (EPIC-01-06);
  - Storage rules (stay deny; voice is Phase 4);
  - the `firebase-functions` major upgrade (separate `upgrade-deps` task; the CLI warns it is outdated).

## Open question for the owner (privacy)
`users/{uid}` mixes public profile fields (`display_name`, `avatar_id`, `bio`) with fields that must not be public: `age_band`, `linked_providers`, `is_suspended`, `is_anonymous`. Firestore rules can't hide single fields, so a readable profile doc exposes a user's minor status to everyone, which is a safety risk.
- **Proposed:** split it into public `users/{uid}`, holding the profile fields and counters, and owner-only `users/{uid}/private/account`, holding the age band, providers, anonymity and suspension. This changes `DataContracts.md` §3.1 and is recorded as an ADR.
- **Alternative:** keep one document, readable by the owner only, until EPIC-01-07, then decide.

This story implements whichever you pick; the proposed split is the default if you approve the story as written.

## Acceptance
1. Every rule in Scope has at least one allow test and one deny test in the emulator suite. Denials cover the other user, the anonymous user and the signed-out user wherever each applies.
2. A fart create with any precise-coordinate key, a non-enum visibility, an out-of-range value, non-zero counters, a client timestamp, or a paid cosmetic without an entitlement is rejected.
3. FOLLOWERS reads:
   - with no follow relation: denied;
   - with an APPROVED relation: allowed;
   - with an APPROVED relation plus a block in either direction: denied.
4. Map-style query shapes:
   - `where visibility_mode == PUBLIC && is_hidden == false && is_removed == false`: allowed;
   - an unconstrained collection query: denied;
   - `where author_user_id == uid`: allowed.
5. `runOnce`:
   - a duplicate delivery is skipped;
   - a failed run is retried on redelivery;
   - an expired lease is re-claimed;
   - records carry `expire_at`, and the TTL override exists.
6. A prod deploy publishes only `health` among the functions; dev publishes all.
7. `npm run build && npm run lint && npm test` passes in CI (the emulator suites run there; locally they need the Firebase CLI), and the dev deploy after merge is green.
