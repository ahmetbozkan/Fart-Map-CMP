# STORY-01-02-01: Anonymous session and the 13+ age gate

Status: Done   Epic: EPIC-01-02   Features: onboarding (Scope.md "Onboarding"), safety (age gating)   ADRs: ADR-0018, ADR-0023, ADR-0025

## Goal
"Continue without account" creates a real, persistent Firebase anonymous session (ADR-0018). Before the first Active session the user declares a birth year once:
- 13+ continues to the map;
- under-13 is blocked.

Only the age band is stored, in the owner-only `users/{uid}/private/account` (ADR-0025). That doc is what the rules read for the adults-only PUBLIC check.

## Scope
- **In:**
  - **`FirebaseSessionRepository` (`firebaseData`):** implements `SessionRepository` with GitLive Auth.
    - **Session state:**
      - `Loading` until the first auth emission;
      - `SignedOut` with no user;
      - `NeedsAgeBand(kind)` when signed in without an account doc;
      - `Active(ANONYMOUS | LINKED)` once the account doc exists. The doc is read through the Firestore listener, so a pending local write already counts and this works offline after the first sign-in.
    - `continueAnonymously()` calls `signInAnonymously` (online-only; offline gives a typed `NetworkUnavailable`).
    - A returning user is restored by Firebase, with no new uid.
  - **`SessionState.NeedsAgeBand`:**
    - added to the domain;
    - root mapping `NeedsAgeBand → AgeGateRoute` (typed route, back stack reset like the other root moves);
    - `app_open` still fires only on `Active`.
  - **Age gate (`feature/onboarding`):**
    - `AgeGateScreen` + `AgeGateViewModel`: a birth-year picker and "Continue", in product-voice strings.
    - The band is computed from the birth year and the current year: 13–17 → `AGE_13_17`, 18+ → `AGE_18_PLUS`. Ambiguous edges resolve to the younger band, which fails safe. The birth year itself is never stored, logged or sent.
    - **13+:** writes `users/{uid}/private/account` (`age_band`; `is_anonymous` from the session; `linked_providers: []`; `is_suspended: false`; server timestamps) through `AppWriteScope`. Rules (STORY-01-01-04) validate it.
    - **Under 13:** a blocked screen in product voice. The anonymous session is signed out, and a device-scoped DataStore flag keeps the gate closed on this install, so the user can't just re-enter a different year (ContentSafety.md §5).
  - **`AccountRepository`:** `core/domain` contract with the `firebaseData` implementation. It observes the account doc and writes it once.
  - **Wiring and tests:**
    - Koin binds the Firebase implementations.
    - `InMemorySessionRepository` moves to test fakes.
    - Auth errors map to `AppError`.
    - Tests:
      - session mapping incl. `NeedsAgeBand`;
      - the age-band calculation at the edges (12/13, 17/18, birthday-year ambiguity);
      - the `AgeGateViewModel` paths (13+, under 13, write rejected, offline);
      - the blocked-device flag;
      - root routing.
- **Out:**
  - **STORY-01-02-02:** the public profile doc (generated funny display name + free starter avatar) and the dev catalog seed of free starter items. The rules require a free catalog avatar, and the catalog is empty in Firestore.
  - **STORY-01-02-03:** Google and Apple sign-in.
  - **STORY-01-02-04:** linking anonymous → Google/Apple (same uid).
  - **STORY-01-02-05:** App Check.
  - **EPIC-01-07:** the sign-out UI and its anonymous warning.

## Acceptance
1. Given a fresh install, when the user taps "Continue without account", then an anonymous Firebase user is created and the age gate shows. Back doesn't return to the auth entry.
2. Given the age gate, when a birth year making the user 13 or older is confirmed, then `users/{uid}/private/account` is written with the right band and the user lands on the Map tab. This also works when the write is still pending (offline after sign-in).
3. Given a birth year making the user under 13, then the blocked screen shows and the session is signed out. Relaunching the app shows the blocked screen again.
4. Given a relaunch after a completed age gate, then the same uid is restored and the app opens straight on the Map tab, with no auth entry and no age gate.
5. Given no network on a fresh install, "Continue without account" shows the offline error, and nothing is written.
6. Given the band calculation, ages 12/13 and 17/18 at year boundaries resolve as specified. The birth year never appears in logs, analytics or Firestore (unit test on the write payload and the logger).
7. `scripts/verify.sh --full` is green, and CI (Android, iOS, backend, secret scan) is green. A manual Android emulator run against `fart-map-dev` shows the account doc in the console. On iOS: the CI build, plus one Mac run when you can.
