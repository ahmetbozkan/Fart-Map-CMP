# STORY-01-02-03: Google sign-in on Android and iOS

Status: Done   Epic: EPIC-01-02   Features: UXF-13 / UXF-01 (auth entry; no `features/` file covers auth)   ADRs: ADR-0018, ADR-0025, ADR-0008

## Goal
A signed-out user can tap "Continue with Google" on the auth entry, on Android and iOS, and gets a real Firebase session on their Google account. A new Google user then passes the 13+ age gate. A returning one goes straight to the map. Apple sign-in is not offered in Phase 1 (owner, issue #14).

## Scope
- **In:**
  - **Contract `core/platform/GoogleSignIn.kt`:** `GoogleIdTokenProvider.requestToken(): GoogleTokenResult`, with the results `Token(idToken, accessToken?)`, `Cancelled` and `Failed(AppError)`.
  - **Android (`shared/src/androidMain`):** Credential Manager with `GetSignInWithGoogleOption`, using the web client id the google-services plugin generates (`default_web_client_id`). The current Activity comes from an `ActivityLifecycleCallbacks` tracker.
  - **iOS:**
    - a Swift `GoogleSignInBridgeImpl` in `iosApp` uses Google's GoogleSignIn SDK (SPM `GoogleSignIn-iOS`, product `GoogleSignIn`), with the iOS client id from `FirebaseApp.app()?.options.clientID`;
    - a build phase registers the reversed client id URL scheme from the injected plist;
    - `umbrella` defines the Swift-facing callback bridge, and the shared `CallbackGoogleIdTokenProvider` adapts it to `GoogleIdTokenProvider`.
  - **Auth:**
    - `AuthGateway.signInWithGoogle(idToken, accessToken)`, implemented in `firebaseData` with GitLive `GoogleAuthProvider.credential` + `signInWithCredential`;
    - `SessionRepository.signInWithGoogle(): AppResult<SignInOutcome>` (`SIGNED_IN` / `CANCELLED`).
  - **Auth entry UI:** "Continue with Google" enabled with an in-progress state, the Apple button and the "coming soon" line removed, and failures shown through the existing typed snackbar.
  - **Session routing:** reuses the existing flow. A new Google uid → `NeedsAgeBand(LINKED)` → age gate → account doc with `is_anonymous = false`, which the rules already check against `sign_in_provider`. An existing account → Active.
  - **Docs:**
    - the Apple deferral recorded in `ROADMAP.md`, `Scope.md`, `Growth.md` (guideline 4.8 before the iOS store release) and this story;
    - STORY-01-02-04 is Google-only and -05 is deferred;
    - `TechStack.md` gets the auth libraries;
    - `Architecture.md` §7 provider list.
- **Out:**
  - Sign in with Apple (Phase 2, owner 2026-11-25).
  - Linking anonymous → Google (STORY-01-02-04).
  - App Check (STORY-01-02-05, deferred).
  - Sign-in analytics events (no event in the typed contract yet; added with the funnel work).
  - Populating `linked_providers` (server-managed; stays `[]` on create, as the rules require).
  - Account deletion.
  - Visual polish (Phase 1 is function first).

## Acceptance
1. Given a signed-out user, when they tap "Continue with Google" and pick an account, then Firebase signs in with a Google credential, `SessionRepository.signInWithGoogle` returns `Success(SIGNED_IN)`, and the session leaves `SignedOut`. Proven by a unit test with a fake gateway and provider, plus the manual run on both platforms.
2. Given a new Google uid with no account doc, then the session is `NeedsAgeBand(LINKED)`. Passing the gate writes the account doc with `isAnonymous = false`. Given a Google uid whose account doc exists, then the session is `Active(kind = LINKED)` with no gate. Proven by unit tests.
3. Given the user dismisses the Google sheet, then the result is `Success(CANCELLED)`. No message is shown, the user stays on the auth entry and the buttons are enabled again. Proven by repository and ViewModel tests.
4. Given a provider or Firebase failure (offline, not configured, rejected credential), then a typed `AppError` reaches the UI as `AuthEvent.ShowMessage`, a structured log names the category only (no token, email or uid), and the user can retry. Proven by tests.
5. While a sign-in runs, a second tap on either button does nothing, and the Google button shows its in-progress state. Proven by a ViewModel test.
6. The auth entry shows Google and "Continue without account", and no Apple button or "coming soon" text, on both platforms.
7. `scripts/verify.sh --full` is green, and CI (Android, iOS app build, backend, secret scan) is green.

## Decisions
- **Apple sign-in?** Moved to Phase 2. The owner decided this on issue #14 (no paid Apple Developer account yet). No Apple button and no stub. App Store guideline 4.8 (an equivalent privacy-focused login when Google is offered) must be met before the iOS store release; recorded in `Growth.md` and `ROADMAP.md`. ADR-0018 still names Apple as an allowed provider; this changes only its timing, so no ADR is reversed.
- **STORY-01-02-04 / -05?** -04 links anonymous → Google only. -05 (App Check) is deferred until the paid Apple account exists (App Attest). It stays a Phase 1, release-blocking item, because ADR-0015 / ADR-0018 §5 make App Check mandatory from Phase 1 and the owner deferred it, not de-scoped it. After -04, EPIC-01-03 starts. Source: owner, issue #14.
- **iOS: GoogleSignIn SDK or our own OAuth?**
  - Choice: Google's GoogleSignIn SDK through SPM (`https://github.com/google/GoogleSignIn-iOS`, up to next major from 9.0.0, product `GoogleSignIn`). It is the vendor-maintained path the Firebase docs prescribe, and it adds no new pattern (a native SDK behind a `core/platform` contract, ADR-0008).
  - A hand-rolled `ASWebAuthenticationSession` PKCE flow was considered and rejected after plan review: we would own security code on the auth path, which is a security-posture call for the owner.
  - **Cost:** the SPM pins (AppAuth, GTMAppAuth and the `app-check` range next to Firebase 13) can only be checked by the CI `ios` job from Windows. If resolution fails, that goes through the retry ladder. `Package.resolved` gets the new pins on the owner's Mac (owner action); CI resolves without them.
  - The SDK raises an exception when the reversed client id URL scheme isn't registered. So:
    - a build phase copies `REVERSED_CLIENT_ID` from the injected plist into the built `Info.plist` `CFBundleURLTypes`, reading only that key with PlistBuddy and never printing it;
    - the Swift bridge checks that the scheme is registered before calling the SDK, and returns `not_configured` instead of crashing.
- **Swift ↔ Kotlin seam?**
  - Swift can't cleanly implement a `suspend` contract, so `umbrella` exposes callback interfaces (`GoogleSignInBridge`, `GoogleSignInCallback`) for Swift to implement.
  - The shared `CallbackGoogleIdTokenProvider` (commonMain, unit-tested) adapts a callback-style start function to `GoogleIdTokenProvider`. It resumes once, maps reasons to `AppError` and logs the category only.
  - This becomes the documented pattern for later Swift capabilities (ads, purchases). One sentence goes in `Architecture.md`.
  - GoogleSignIn has no cancel API. A cancelled coroutine ignores the late callback, and the SDK sheet stays up until the user closes it.
- **Where does the client id come from?**
  - iOS: `FirebaseApp.app()?.options.clientID` (the `CLIENT_ID` of the injected plist).
  - Android: the `default_web_client_id` string the google-services plugin generates from the injected json, looked up by name at runtime. A compile-time `R.string` reference would break every build whose json predates the Google provider (CI secrets).
  - On both: missing → `Failed(Unknown)` plus the structured log `google_not_configured`; never a crash.
  - Source: tie-break (fail closed, no secrets in git; these are config values, read through the SDKs only).
- **Android API?** Credential Manager (`androidx.credentials` + `googleid`, already in the catalog) with `GetSignInWithGoogleOption`, the explicit-button flow, since the user tapped a button. The legacy `play-services-auth` GoogleSignIn is deprecated.
- **Where does the Android Activity come from?** An `ActivityLifecycleCallbacks` tracker registered from the Koin `androidContext()` Application in `shared/src/androidMain`. It keeps the shell logic-free (`android-shell.md`) and keeps `Context` out of ViewModels.
- **Cancel?** Silent: no snackbar, buttons re-enabled (`AuthLoginScreen.md` lists errors, not cancellations).
- **Error categories?** The existing `AppError` set: `NetworkUnavailable` for offline, `Unknown` for everything else, including a rejected credential. `AuthExpired` reads "Your session went stale", which would mislead on a first sign-in. No new category, so `Observability.md` §4 doesn't change. Logs carry the category, and the `Logger` already redacts throwables (`Redaction.sanitize`, `LoggerTest`).
- **Rules tests?** No rule changes. The Google path is already covered by `users.rules.test.ts`:
  - account create with `is_anonymous: false` under a `google.com` context is allowed (base `account()` + `user()`);
  - `is_anonymous: true` under `google.com` is denied (line 80);
  - `false` under `anonymous` is denied (line 79).
- **Session kind for a Google user?** `LINKED`, the existing non-anonymous kind (`SessionState.Kind`), so no new state.
- **`linked_providers`?** Stays `[]` on create. The rules require it and DataContracts/ADR-0025 make it server-managed; the server fills it when linking ships. Nothing reads it in Phase 1.
- **Analytics?** Not in this story. `Observability.md` lists sign-in start/success/failure, but there is no typed event for it yet. It goes in with the funnel instrumentation (EPIC-01-11) so the event contract changes once.

## Plan
**shared / commonMain**
- `core/platform/GoogleSignIn.kt`:
  - `interface GoogleIdTokenProvider { suspend fun requestToken(): GoogleTokenResult }`;
  - `sealed interface GoogleTokenResult { data class Token(val idToken: String, val accessToken: String?); data object Cancelled; data class Failed(val error: AppError) }`;
  - `Token.toString()` redacts both tokens.
- `core/domain/session/Identity.kt`: `AuthGateway.signInWithGoogle(idToken: String, accessToken: String?): AppResult<Unit>`.
- `core/domain/session/SessionRepository.kt`: `enum class SignInOutcome { SIGNED_IN, CANCELLED }`, and `suspend fun signInWithGoogle(): AppResult<SignInOutcome>` (online-only, never queued).
- `core/data/session/DefaultSessionRepository.kt`: a new constructor param `googleTokens: GoogleIdTokenProvider`. `signInWithGoogle()` maps `Token` → `auth.signInWithGoogle(...).map { SIGNED_IN }`, `Cancelled` → `Success(CANCELLED)`, `Failed(e)` → `Failure(e)`.
- `feature/auth/presentation`:
  - `AuthState(inProgress: AuthMethod? = null)` with `isWorking` derived; `enum AuthMethod { GOOGLE, GUEST }`; `AuthAction.ContinueWithGoogle`;
  - the ViewModel guards re-entry, and on `CANCELLED` stays silent;
  - `AuthScreen` enables the Google button, shows a small progress indicator in it while `inProgress == GOOGLE`, and drops the Apple button and the coming-soon text;
  - strings: remove `auth_apple` and `auth_coming_soon`, and change `auth_google` to "Continue with Google" if it isn't already;
  - previews for idle, Google in progress and guest in progress.
- `core/di/SharedModules.kt`: pass `googleTokens = get()`.

**shared (androidMain source set)**
- `core/platform/CurrentActivityTracker.kt`: registers `Application.ActivityLifecycleCallbacks` and holds a `WeakReference` to the last resumed Activity.
- `core/platform/AndroidGoogleIdTokenProvider.kt`:
  - `CredentialManager.create(activity).getCredential(activity, GetCredentialRequest(GetSignInWithGoogleOption.Builder(webClientId).build()))`;
  - takes a `CustomCredential` of type `GoogleIdTokenCredential.TYPE_GOOGLE_ID_TOKEN_CREDENTIAL` → `GoogleIdTokenCredential.createFrom(data).idToken`;
  - maps `GetCredentialCancellationException` → `Cancelled`; `NoCredentialException`, `GetCredentialException` and `GoogleIdTokenParsingException` → `Failed` (`NetworkUnavailable` when the type says network, else `Unknown`), each logged by category;
  - no Activity or no web client id → `Failed(Unknown)` + `google_not_configured` (or `no_activity`);
  - the web client id is found with `resources.getIdentifier("default_web_client_id", "string", packageName)`, falling back to the namespace package;
  - `@SuppressLint("DiscouragedApi")` on that one call, with the reason: the resource exists only when the injected json has a web client, so a compile-time reference would break those builds. This is a documented necessity, not a way to get lint green.
- `PlatformModule.android.kt`: binds `CurrentActivityTracker` (created eagerly with the Application) and `GoogleIdTokenProvider`.
- `shared/build.gradle.kts` androidMain: `androidx-credentials`, `androidx-credentials-playServicesAuth`, `googleid`.

**shared / commonMain (iOS seam, tested)**
- `core/platform/CallbackGoogleIdTokenProvider.kt`: `class CallbackGoogleIdTokenProvider(start: (GoogleTokenCallback) -> Unit, logger: Logger) : GoogleIdTokenProvider`.
  - `GoogleTokenCallback` has `onToken(idToken, accessToken?)`, `onCancelled()` and `onFailure(reason: String)`.
  - `suspendCancellableCoroutine` with a resume-once guard; a late or duplicate callback is ignored.
  - Reasons: `network` → `NetworkUnavailable`; `not_configured` / `failed` / anything else → `Unknown`.
  - `not_configured` logs `google_not_configured`; the others log `google_sign_in_failed`, with the category only. The reason string never reaches the log as free text, only as the mapped event.
  - An empty `idToken` → `Failed(Unknown)`.

**shared / iosMain**: nothing.

**umbrella / iosMain**
- `GoogleSignInBridge.kt`:
  - `interface GoogleSignInBridge { fun signIn(callback: GoogleSignInCallback) }`;
  - `interface GoogleSignInCallback { fun onToken(idToken: String, accessToken: String?); fun onCancelled(); fun onFailure(reason: String) }`;
  - both are Swift-facing.
- `AppStartup.kt`: `startApp(environmentName: String, googleSignIn: GoogleSignInBridge)` adds a module that binds `GoogleIdTokenProvider` to a `CallbackGoogleIdTokenProvider`. Its start function calls `googleSignIn.signIn` with a `GoogleSignInCallback` that forwards to the shared callback.

**iosApp**
- `project.pbxproj`:
  - an `XCRemoteSwiftPackageReference` for GoogleSignIn-iOS (up to next major from 9.0.0), with its product dependency and Frameworks entry for `GoogleSignIn`;
  - a "Register Google URL Scheme" run-script phase after "Copy Firebase Config". It reads `REVERSED_CLIENT_ID` from the copied plist with `/usr/libexec/PlistBuddy` into a variable and adds `CFBundleURLTypes:0:CFBundleURLSchemes:0` to `$TARGET_BUILD_DIR/$INFOPLIST_PATH`. A missing key prints a `warning:` and continues; the value is never printed.
- `GoogleSignInBridgeImpl.swift`:
  - `NSObject, GoogleSignInBridge`;
  - checks `FirebaseApp.app()?.options.clientID`, and that the reversed scheme is present in `Bundle.main` `CFBundleURLTypes`; otherwise `onFailure("not_configured")`;
  - sets `GIDSignIn.sharedInstance.configuration = GIDConfiguration(clientID:)`, then calls `signIn(withPresenting:)` on the main thread from the top-most view controller of the key window;
  - result → `onToken(user.idToken.tokenString, user.accessToken.tokenString)`;
  - `GIDSignInError.canceled` → `onCancelled`; an `NSURLErrorDomain` error → `onFailure("network")`; any other error, or no presenter → `onFailure("failed")`;
  - logs nothing itself.
- `iOSApp.swift`: `.onOpenURL { GIDSignIn.sharedInstance.handle($0) }` on the root view.
- `AppDelegate.swift`: `AppStartupKt.startApp(environmentName: env, googleSignIn: GoogleSignInBridgeImpl())`.

**firebaseData**
- `FirebaseAuthGateway.signInWithGoogle` = `authCall("sign_in_google") { Firebase.auth.signInWithCredential(GoogleAuthProvider.credential(idToken, accessToken)) }`. It uses the existing mapping (network → `NetworkUnavailable`, else `toAppError()`) and the existing structured `auth_failed` log.
