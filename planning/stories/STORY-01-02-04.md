# STORY-01-02-04: Link anonymous → Google

Status: Done   Epic: EPIC-01-02   Features: UXF-01 (auth / account linking; no `features/` file covers auth)   ADRs: ADR-0018, ADR-0025, ADR-0006, ADR-0021

## Goal
A guest (anonymous session) can link their Google account from the Profile tab, on Android and iOS. They keep the same uid, so their content, entitlements and settings carry over, and the app doesn't move them off the screen they are on. Afterwards the session is `Active(LINKED)` and the server marks the private account doc as no longer anonymous.

## Scope
- **In:**
  - **Domain:** `AuthGateway.linkGoogle(idToken, accessToken)`, `AccountRepository.observeProvidersStale(uid)` + `syncLinkedProviders()`, `SessionRepository.linkGoogle(): AppResult<LinkOutcome>` (`LINKED` / `CANCELLED`).
  - **`AccountProviderSync`** (eager, like `ProfileBootstrap`): on `Active(LINKED)` with a stale account doc, calls the server sync once per uid per process. This also fills `linked_providers` for users who signed in with Google directly.
  - **Session:** a link changes `Active(uid, ANONYMOUS, band)` to `Active(uid, LINKED, band)` with no `Loading` in between, so the root never navigates and the back stack survives (`Architecture.md` §7).
  - **firebaseData:** GitLive `currentUser.linkWithCredential(GoogleAuthProvider.credential(...))`; a collision (the Google account already has its own uid) maps to `AppError.Conflict`. The gateway re-emits the user after a link, because Firebase's auth-state listener doesn't fire when the uid stays the same. A new GitLive `firebase-functions` dependency calls the `syncAccountProviders` callable.
  - **Backend:** the callable `syncAccountProviders` (v2, `europe-west1`). It reads the caller's providers from the Admin Auth record and updates `is_anonymous`, `linked_providers` and `updated_at` on `users/{uid}/private/account` (server-managed per `DataContracts.md` §3.1.1 / ADR-0025). Handler + emulator test. Added to `PROD_FUNCTIONS`.
  - **iOS:** the `FirebaseFunctions` SPM product, which GitLive's iOS functions module links against.
  - **UI:** the Profile tab placeholder gets a link card for anonymous sessions: "Link Google", in-progress state, a typed snackbar on failure and a success snackbar. Linked sessions see the plain placeholder.
  - **Docs:** `DataContracts.md` §3.1.1 names the mechanism; `TechStack.md` gets the functions library; `ROADMAP.md` gets the deferred link surfaces (Rank card → EPIC-01-07, post-first-log nudge → EPIC-01-04).
- **Out:**
  - The post-first-log nudge (needs logging, EPIC-01-04) and the Rank tab link card (Rank screen, EPIC-01-07). Profile is the surface ADR-0018 names.
  - Switching to the Google account's other uid after a collision (would abandon the guest's content). The user stays on the guest session.
  - Apple (Phase 2), App Check (STORY-01-02-05, deferred), the anonymous sign-out warning (Settings, EPIC-01-07), analytics `account_linked` / `account_link_prompted` (funnel work, EPIC-01-11, same reasoning as STORY-01-02-03).
  - Visual polish (Phase 1 is function first).

## Acceptance
1. Given an `Active(ANONYMOUS)` session, when the user taps "Link Google" on Profile and picks an account, then Firebase links the credential to the same uid, `SessionRepository.linkGoogle` returns `Success(LINKED)`, and the session becomes `Active(sameUid, LINKED, sameBand)` without passing through `Loading`, `NeedsAgeBand` or `SignedOut`. Proven by repository tests with fakes, plus a `rootNavigationFor` test that this change keeps the current route.
2. Given an `Active(LINKED)` session whose server-confirmed account doc still says `is_anonymous = true` or has empty `linked_providers`, the client calls `syncAccountProviders` (at most once per uid per process; a failure is logged and retried on a later launch). The function sets `is_anonymous = false`, `linked_providers = ["google"]` and `updated_at` on the caller's account doc, uses only `request.auth.uid` (ignoring `request.data`), refuses unauthenticated calls, and changes nothing when the doc doesn't exist. Proven by backend unit + emulator tests of the handler and the auth wrapper, and by `AccountProviderSync` tests. A sync failure never fails the link (the link already happened in Firebase Auth).
3. Given the user dismisses the Google sheet, then the result is `Success(CANCELLED)`, nothing is shown, and the card is enabled again. Proven by repository and ViewModel tests.
4. Given the Google account already belongs to another Fart Map account, then the result is `Failure(Conflict)`, the user stays on the same guest uid, and the snackbar says so in the product voice. Given offline or another failure, a typed message is shown and a retry works. Logs name the category only (no token, email or uid). Proven by tests.
5. While a link runs, a second tap does nothing and the card shows progress. Proven by a ViewModel test.
6. The link card shows only for anonymous sessions; a linked session never sees it. Proven by a ViewModel test and previews.
7. `scripts/verify.sh --full` is green, and CI (Android, iOS app build, backend, secret scan) is green.

## Decisions
- **Where can a guest link in this story?** The Profile tab. ADR-0018 §3 names "from the profile"; the Profile and Rank screens are placeholders until EPIC-01-07 and the post-log nudge needs logging (EPIC-01-04). The Rank card and the nudge are added to those epics in `ROADMAP.md`. Source: ADR-0018, `UXFlowCatalog.md` UXF-01, tie-break (simplest surface that exists).
- **Google account already linked to another uid (`credential-already-in-use`)?** No spec covers it. Decision: fail with `AppError.Conflict`, stay on the guest uid, and say so ("That Google account already has its own Fart Map. You're still here as a guest."). Signing in to the other uid would orphan the guest's content, and merging two accounts is not in any spec. Source: tie-break (no data loss, simpler); ADR-0018 §3 (linking keeps the uid).
- **Who writes `is_anonymous` / `linked_providers` after a link?** They are server-managed (ADR-0025, `DataContracts.md` §3.1.1) and no mechanism was named. Decision: a callable `syncAccountProviders` that derives both fields from the Admin Auth record of `request.auth.uid`; it takes no input. The rules stay unchanged (the owner still can't update the doc). Rejected:
  - opening a rules path for the owner to flip the fields: changes a server-managed contract and the security rules;
  - an Auth blocking function: needs Identity Platform (an owner console action);
  - not syncing at all: `DataContracts.md` says `is_anonymous` "flips to false on account linking", and STORY-01-02-03 deferred the fill to this story.
- **New dependency `dev.gitlive:firebase-functions`?** Yes, in `firebaseData` only (same GitLive version and pattern as the other Firebase modules, ADR-0021), plus the matching `FirebaseFunctions` SPM product on iOS. No new pattern, so no ADR; recorded in `TechStack.md`.
- **When does the client call the sync, and what if it fails?** Not inside `linkGoogle`: an eager `AccountProviderSync` watches the session, and for `Active(LINKED)` reads the server-confirmed account doc (no pending writes). If it is stale (`is_anonymous` true or `linked_providers` empty), it calls the callable once per uid per process. A failure is logged (`account_sync_failed`, category only) and retried on the next launch; a healthy doc costs no call. The link itself always reports success, because Firebase Auth already holds it. The same path fills `linked_providers` for direct Google sign-ins, whose doc the rules force to `[]` on create. Source: `DataContracts.md` (flips on linking), plan review round 1.
- **Is linking specced, given no `features/` file covers auth?** Yes: ADR-0018 §3 (Accepted) and `UXFlowCatalog.md` UXF-01 define it, which satisfies the "feature must be specced" stop rule, as in STORY-01-02-01..03.
- **The callable without App Check?** It is auth-gated, takes no input, only writes the caller's own server-managed fields from the Admin Auth record, and is idempotent. App Check enforcement for all callables lands with STORY-01-02-05 (deferred, release-blocking in STATE).
- **Dead end after a conflict?** A returning Google user who started as a guest can't reach their real account until sign-out exists (Settings, EPIC-01-07, with the ADR-0018 §4 warning). Recorded in `ROADMAP.md` under EPIC-01-07.
- **Session flow on link?** Firebase keeps the uid, so the session is re-derived per uid: the account-doc listener is keyed by uid, and the kind follows the latest user for that uid. That way no `Loading` blip happens and the root keeps `MainRoute` (`Architecture.md` §7: "linking leaves the session, uid and back stack unchanged").
- **Re-emitting the user after a link?** Firebase's auth-state listener fires on sign-in and sign-out only. The gateway merges its auth-state flow with a flow it feeds after a successful link (the current user, now non-anonymous). Deterministic on both platforms, without relying on token-refresh timing.
- **Link on a non-anonymous or missing session?** No user → `Failure(AuthExpired)`; already linked → `Success(LINKED)` without opening the sheet. The UI only offers it to anonymous sessions anyway.
- **Age gate on link?** None: the guest already declared an age band, and the doc (with its immutable `age_band`) stays under the same uid.
- **Online-only?** Yes, never queued (`LocalData.md` §2, `kotlin-shared.md`). Offline → `NetworkUnavailable` message.
- **Feature boundaries?** The link card lives in `feature/profile`; it uses `SessionRepository` from `core/domain` and doesn't import `feature/auth`.
- **Analytics?** Deferred to EPIC-01-11 like the sign-in events (`Observability.md` lists `account_linked`).

## Plan
**shared / commonMain**
- `core/domain/session/Identity.kt`: `AuthGateway.linkGoogle(idToken: String, accessToken: String?): AppResult<Unit>` (Conflict when the credential belongs to another account); `AccountRepository.observeProvidersStale(uid): Flow<Boolean>` (server-confirmed snapshots only: true when `is_anonymous` or `linked_providers` is empty; nothing while the doc is missing or pending) and `suspend fun syncLinkedProviders(): AppResult<Unit>` (calls the server; online-only).
- `core/domain/session/SessionRepository.kt`: `enum class LinkOutcome { LINKED, CANCELLED }`; `suspend fun linkGoogle(): AppResult<LinkOutcome>`.
- `core/data/session/DefaultSessionRepository.kt`:
  - `linkGoogle()`: current user null → `Failure(AuthExpired)`; not anonymous → `Success(LINKED)`; else request a token (`Cancelled` → `Success(CANCELLED)`, `Failed` → `Failure`), then `auth.linkGoogle(...).map { LINKED }`.
  - Session flow: `userState` is split into a uid key (`Unknown` / `SignedOut` / uid) with `distinctUntilChanged`, `flatMapLatest` on that key; for a uid, `combine(accounts.observeAgeBand(uid), userState.kindFor(uid).distinctUntilChanged())` with `onStart { emit(Loading) }`. `kindFor(uid)` takes only users with that uid.
- `core/data/session/AccountProviderSync.kt` (eager single in the shared `dataModule`, which both the Android and the iOS Koin compositions load; started like `ProfileBootstrap`): `session.map { (it as? Active)?.takeIf { kind == LINKED }?.uid }.distinctUntilChanged().flatMapLatest { uid -> uid?.let { accounts.observeProvidersStale(it).filter { stale -> stale }.take(1).map { uid } } ?: emptyFlow() }`, and for each uid not yet attempted in this process: `syncLinkedProviders()` (the implementation logs failures).
- `firebaseData`: the stale rule is a pure function on the DTO (`AccountProvidersDto.isStale`), unit-tested for missing fields, an empty array and a healthy doc.
- `feature/profile/presentation`:
  - `ProfileState(canLink: Boolean = false, linking: Boolean = false)`; `ProfileAction.LinkGoogle`; `ProfileEvent.ShowMessage(AppError)`, `ProfileEvent.LinkConflict`, `ProfileEvent.Linked`.
  - `ProfileViewModel(sessions)`: collects the session; `canLink = session is Active && kind == ANONYMOUS`; re-entry guard; `CANCELLED` silent; `LINKED` → `Linked`; `Failure(Conflict)` → `LinkConflict`; other failures → `ShowMessage`. The route only maps events to strings.
  - `ProfileScreen.kt`: `ProfileRoute` (collects VM, snackbar host) + stateless `ProfileScreen(state, onAction)`: the existing placeholder, plus a link card (title, body, a button with a progress indicator) when `canLink`. Tokens only. Previews: linked, guest, guest linking.
  - Strings: `profile_link_title`, `profile_link_body`, `profile_link_button`, `profile_link_success`, `profile_link_conflict`.
- `core/navigation/MainShell.kt`: `composable<TabRoute.Profile> { ProfileRoute() }`.
- `core/di/SharedModules.kt`: `viewModelOf(::ProfileViewModel)`.

**firebaseData**
- `build.gradle.kts` + `libs.versions.toml`: `gitlive-firebase-functions` (version ref `gitlive`).
- `FirebaseAuthGateway`:
  - `user` = `merge(authStateChanged.map(::toAuthUser), linkedUsers)`; `linkedUsers` is a `MutableSharedFlow<AuthUser>(extraBufferCapacity = 1)`;
  - `linkGoogle` = `authCall("link_google") { val u = currentUser ?: throw no-user → AuthExpired; u.linkWithCredential(credential); linkedUsers.emit(toAuthUser(currentUser)) }`;
  - `authCall` maps `FirebaseAuthUserCollisionException` → `Conflict` (before the generic branch), logged as `auth_failed` with the category only.
- `FirestoreAccountRepository.observeProvidersStale(uid)`: the account-doc snapshots, skipping missing docs, cache-only and pending-write snapshots; reads `is_anonymous` and `linked_providers` with a small DTO (missing fields read as stale); listener failures logged and retried like `observeAgeBand`.
- `FirestoreAccountRepository.syncLinkedProviders()` = `Firebase.functions(REGION).httpsCallable("syncAccountProviders").invoke()`, wrapped like `authCall` (network → `NetworkUnavailable`, else `toAppError()`), failure logged as `account_sync_failed`. `REGION = "europe-west1"` lives next to it with a comment pointing at `backend/functions/src/region.ts`.

**backend/functions**
- `src/callables/syncAccountProviders.ts`:
  - pure `accountProvidersFrom(providerIds: string[])` → `{ is_anonymous, linked_providers }`: `google.com` → `google`, `apple.com` → `apple`, others ignored, sorted and de-duplicated; `is_anonymous = linked_providers.length === 0`;
  - `syncAccountProviders(db, uid, providerIds)`: reads `users/{uid}/private/account`; missing → `"missing"`; else `update({ ...fields, updated_at: FieldValue.serverTimestamp() })` → `"updated"`.
  - `handleSyncAccountProviders(deps: { db, lookupProviders(uid) }, auth: { uid } | undefined)`: no auth → `HttpsError("unauthenticated")`; looks up `auth.uid` only (the caller's data is never passed in); a lookup failure → `HttpsError("internal")`, logged through `src/lib/log.ts` with the outcome only (no uid or email); returns `{ status }`.
- `src/index.ts`: `export const syncAccountProviders = onCall({ region: REGION }, (request) => handleSyncAccountProviders({ db: getFirestore(), lookupProviders: uid => getAuth().getUser(uid).then(u => u.providerData.map(p => p.providerId)) }, request.auth))`. `request.data` is ignored.
- Tests: `test/accountProviders.test.ts` (unit: mapping; wrapper with a fake db/lookup: no auth → `unauthenticated`, lookup called with `auth.uid`, lookup failure → `internal` and no uid in the log); `test/emulator/syncAccountProviders.test.ts` (Admin SDK on the Firestore emulator through `handleSyncAccountProviders`: updates an existing doc, keeps `age_band` / `is_suspended` / `created_at`, missing doc → `missing` with no doc created, idempotent on a re-run).
- `.github/workflows/deploy-backend.yml`: `PROD_FUNCTIONS: functions:health,functions:syncAccountProviders`.
- Rules: unchanged. The existing `users.rules.test.ts` cases already deny an owner update of the account doc (lines 96–99).
