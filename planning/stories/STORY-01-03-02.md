# STORY-01-03-02: Map host on both platforms

Status: In progress   Epic: EPIC-01-03   Features: MAP-01, MAP-02   ADRs: ADR-0008, ADR-0019, ADR-0021

## Goal
The Map tab, the launch screen, shows a real interactive map with native gestures: Google Maps on Android and MapKit on iOS, behind one shared contract. The contract renders a list of shared marker models and reports marker taps and the visible viewport, so STORY-01-03-03 only has to supply data.

## Scope
- **In:**
  - **Contract, `shared` `core/platform/MapHost.kt`:** `interface MapHost` with a single `@Composable fun Map(markers, initialCamera, onMarkerTap, onViewportChange, modifier)`, plus `MapMarker(id, lat, lng, contentDescription)`. Only domain-safe types; no SDK type crosses it.
  - **Pure geometry types, `core/domain/location`:** `MapCamera(lat, lng, zoom)` with the zoom → span conversion MapKit needs, and `MapViewport(south, west, north, east)` with its normalising constructor `fromCenterSpan(...)` (clamped latitude; antimeridian crossing shown as `west > east`). These are what -03's `observeMapFarts(viewport, filter)` takes.
  - **Android:** `GoogleMapsMapHost` in `shared/src/androidMain` (maps-compose). The key goes from `secrets.properties` → a manifest placeholder → `com.google.android.geo.API_KEY` (replaces the unused `MAPS_API_KEY` BuildConfig field).
  - **iOS:** `MapKitMapHost` in `shared/src/iosMain`, Kotlin over `platform.MapKit` (`MKMapView` in `UIKitView`), with a Kotlin `MKMapViewDelegateProtocol`. `-framework MapKit` goes into the app's `OTHER_LDFLAGS`, because the Kotlin framework is static.
  - **Koin:** each platform module binds `MapHost`.
  - **Map feature:** `MapState` / `MapAction` / `MapViewModel` (`StateViewModel`) holding the camera, the markers (empty until -03), the last viewport and the tapped marker id. `MapRoute` + stateless `MapScreen(state, mapHost, onAction)` replace the placeholder. `StaticMapHost` (commonMain) serves previews and tests.
- **Out:**
  - Data: the viewport query, filters, loading/empty/error/offline states and analytics events (-03). Until then the map shows no markers.
  - Device location, permission, "center on me" (-04).
  - The marker detail sheet (EPIC-01-05). A tap is recorded in state only.
  - The flavor → marker visual mapping, the marker drop animation and map styling (no spec yet; see Decisions).
  - The overlay app bar, filter row and FAB from `MapScreen.md` (-03 / EPIC-01-04 add them as they get behaviour).

## Acceptance
1. Given a signed-in user, when the app opens, then the Map tab shows a full-screen native map (Google Maps on Android, MapKit on iOS) at the default camera, with pan, zoom and rotate gestures, and no location permission prompt.
2. **Contract and compile here; behaviour proven in -03.** Both hosts implement marker rendering: each `MapMarker` at its lat/lng with its `contentDescription` as the accessibility label (Android `Marker.contentDescription`; iOS `accessibilityLabel` on the annotation view, callout and title hidden); markers that leave the list are removed (iOS diffs annotations by id). This story ships no marker data, so on-device proof is -03's acceptance and the EPIC-01-03 test plan (seeded farts, both platforms, VoiceOver/TalkBack).
3. **Contract and compile here; behaviour proven in -03.** A marker tap calls `onMarkerTap(id)` once, and tapping the same marker again calls it again (Android consumes the click; iOS deselects after reporting). Same proof path as 2.
4. Given the camera comes to rest (after the first layout, and after each gesture), then `onViewportChange` fires with the visible bounds as a `MapViewport`: latitude clamped to ±90, longitude in −180..180, `west > east` when the view crosses the antimeridian, and the whole world when the span is ≥ 360°. Extreme or invalid regions from the SDK never crash: spans are clamped, and a non-finite region is skipped with a structured log.
5. Given `MapViewModel`, then the initial state has the default camera and no markers, `ViewportChanged` stores the viewport (an equal viewport doesn't re-emit), and `MarkerTapped` stores the id.
6. `MapCamera.span` and `MapViewport.fromCenterSpan` are unit-tested for the cases in 4, including the clamped extremes and `null` for non-finite input; an invalid `MapCamera` throws (it's built from constants and -04's validated fixes).
7. `scripts/verify.sh --full` is green; CI (Android, iOS link + xcodebuild, backend, secret scan) is green.

## Decisions
- **Seam (ADR-0008 vs `Architecture.md`).** ADR-0008's title says expect/actual; `Architecture.md` §(platform code) and `.claude/rules/kotlin-shared.md` refine it: SDK-backed capabilities use an interface implemented per platform and bound through Koin. A map is SDK-backed, so `MapHost` is an interface whose one member is a composable. That is the more specific, more recent rule, not a conflict. `StaticMapHost` (previews, tests) is the second implementation.
- **iOS in Kotlin, not Swift.** `platform.MapKit` is available to Kotlin/Native, and `UIKitView` hosts an `MKMapView` directly, so no Swift bridge or `umbrella` entry-point parameter is needed. The platform-capability skill allows either; Kotlin keeps the iOS code in the same module as the contract and its CI compile. Swift stays reserved for SDKs that have no usable Kotlin binding.
- **Default camera.** No spec gives a value (`Scope.md` "centered on user location" is -04's job, and the permission timing is pending with the owner). -02 uses a fixed camera: Istanbul `41.0082, 28.9784`, zoom 12. It's the same center as the dev fart seed, so the EPIC-01-03 test plan shows markers without panning. Asking for nothing at launch fits both `Growth.md` §2 ("never at launch") and the recommended default in STATE, so this doesn't pre-empt the pending decision; -04 replaces the camera once the decision exists.
- **Flavor-styled markers deferred.** `Scope.md` wants "marker visual style reflects flavor level", but no doc maps a flavor to a visual, and adding colour tokens that aren't in `DesignSpecification.md` breaks the tokens-only rule. Phase 1 builds function first and design later (STATE "Decided"). -02 renders the platform default pin; `MapMarker` gets a style field when the spec defines one (no later than the map design pass). The accessibility label (`DesignSpecification.md` §a11y, "Fart by [username], [flavor], [time ago]") is part of the model now, so meaning never rides on colour.
- **Viewport, not zoom.** The host reports visible bounds only. -03 picks the geohash precision from the bounds' size, so a zoom value in the report would be redundant and mean different things on the two SDKs.
- **Antimeridian.** `west > east` marks a crossing (Google's `LatLngBounds` convention, and MapKit's region normalised to it). -03's range cover splits it into two ranges.
- **Zoom on iOS.** MapKit has no zoom level. The camera converts with the Web Mercator relation `lngSpan = 360 / 2^zoom × widthPoints / 256`, with `latSpan = lngSpan × cos(lat)`; MapKit fits the region to the view's aspect.
- **Missing Android key.** The build stays green with an empty key (CI has none), and the Maps SDK logs an authorization failure and shows blank tiles, which the Validation step names. The app doesn't crash.
- **Map UI chrome.** Google's zoom buttons, map toolbar and my-location button are off: the FAB and "center on me" take that space later, and gestures cover zoom. MapKit's defaults stay as they are.
- **Screen states.** `MapScreen.md` lists Loading / Empty / Success / Error / Offline. They all concern the marker data, which -03 owns; the base map is always visible ("base map visible while marker layer hydrates"). -02 renders only the base map.
- **Marker coordinates.** `MapMarker.lat/lng` are whatever the caller supplies: the fuzzed public point for others' farts (ADR-0019, `MapScreen.md` privacy), the precise point only for the owner's own. The host never displays coordinate text (no titles, no callouts). KDoc on `MapMarker` says so.
- **`MapEvent` is empty on purpose:** `StateViewModel` needs the type; -03 and EPIC-01-05 add members when they have one-time effects.
- **SDK regions are untrusted input.** `fromCenterSpan` clamps spans and returns `null` for non-finite input instead of throwing; the iOS host logs the skip as a structured warning. Throwing inside an Objective-C delegate callback would crash the app.
- **MapKit link flag** goes in `Config.xcconfig`, which every configuration includes, instead of hand-editing four `OTHER_LDFLAGS` blocks in the pbxproj.
- **maps-compose version.** Pinned in the catalog; the version Gradle resolved is recorded in Evidence. The headless session can't browse Maven to confirm it's the latest.

## Plan
**`shared/src/commonMain`**
- `core/domain/location/MapCamera.kt`: `data class MapCamera(lat, lng, zoom: Float)` (validated with `Geohash.requireCoordinates`, zoom 0..21) with `fun span(widthPoints: Double): MapSpan` and `data class MapSpan(latDelta, lngDelta)`.
- `core/domain/location/MapViewport.kt`: `data class MapViewport(south, west, north, east)` with `crossesAntimeridian`. `companion fun fromCenterSpan(centerLat, centerLng, latDelta, lngDelta): MapViewport?`: `null` for any non-finite input; clamps the center and the spans (negative → 0, lat ≤ 180); clamps latitude bounds; wraps longitude only when it falls outside ±180 (so 180 stays 180); whole world when `lngDelta >= 360`.
- `core/platform/MapHost.kt`: `interface MapHost { @Composable fun Map(markers: List<MapMarker>, initialCamera: MapCamera, onMarkerTap: (String) -> Unit, onViewportChange: (MapViewport) -> Unit, modifier: Modifier) }`; `data class MapMarker(id, lat, lng, contentDescription)` with the coordinate KDoc (Decisions).
- `core/platform/StaticMapHost.kt`: a token-coloured `Box` with the marker count; no Koin, used by previews and tests.
- `feature/map/presentation/MapState.kt`: `MapState(camera = DEFAULT_CAMERA, markers = emptyList(), viewport = null, selectedMarkerId = null)`; `MapAction.ViewportChanged(viewport)`, `MapAction.MarkerTapped(id)`; `MapEvent` (empty sealed interface, filled by -03/EPIC-01-05).
- `feature/map/presentation/MapViewModel.kt`: reduces both actions; an equal viewport is a no-op.
- `feature/map/presentation/MapScreen.kt`: `MapRoute(viewModel = koinViewModel(), mapHost = koinInject())` → `MapScreen(state, mapHost, onAction, modifier)`, which calls `mapHost.Map(...)` full-size. Previews use `StaticMapHost` (empty and with markers).
- `MainShell`: `composable<TabRoute.Map> { MapRoute() }`. `SharedModules`: `viewModelOf(::MapViewModel)`.
- Remove the two `placeholder_map_*` strings (only the placeholder used them).

**`shared/src/androidMain`** — `core/platform/GoogleMapsMapHost.kt`:
- `GoogleMap(modifier, cameraPositionState = rememberCameraPositionState { position = CameraPosition.fromLatLngZoom(...) }, uiSettings = MapUiSettings(zoomControlsEnabled = false, mapToolbarEnabled = false, myLocationButtonEnabled = false))`.
- Markers: `key(marker.id) { Marker(state = remember(lat, lng) { MarkerState(LatLng(lat, lng)) }, contentDescription = ..., title = null, onClick = { onMarkerTap(id); true }) }` (returning `true` suppresses the info window and the camera jump).
- Viewport: a remembered `mapLoaded` flag set by `GoogleMap(onMapLoaded = …)`; `LaunchedEffect` over `snapshotFlow { mapLoaded && !cameraPositionState.isMoving }.filter { it }` → `projection?.visibleRegion?.latLngBounds` → `MapViewport(south, west, north, east)` (Google already uses the `west > east` convention). So the first viewport fires on load and then after every gesture; the ViewModel dedups.
- `rememberUpdatedState` for both callbacks. Koin: `single<MapHost> { GoogleMapsMapHost() }`.
- Gradle: `maps-compose` in the catalog and in `shared` `androidMain`; `androidApp` manifest `<meta-data android:name="com.google.android.geo.API_KEY" android:value="${mapsApiKey}"/>` with `manifestPlaceholders["mapsApiKey"]` per flavor.

**`shared/src/iosMain`** — `core/platform/MapKitMapHost.kt`:
- `remember { MKMapView() }`, a remembered delegate (MKMapView holds it weakly) and an id → `FartAnnotation` (an `MKPointAnnotation` subclass carrying the id and the label) map.
- The initial region is applied once the view has a size: `Modifier.onSizeChanged` → width in points (÷ density) → `MapCamera.span(width)` → `setRegion(animated = false)`. Setting it makes MapKit call `regionDidChangeAnimated`, which emits the first viewport.
- `UIKitView(factory = { mapView }, modifier, properties = UIKitInteropProperties(interactionMode = NonCooperative, isNativeAccessibilityEnabled = true))`, so map gestures don't wait for Compose and VoiceOver reaches the annotations.
- `LaunchedEffect(markers)`: diff by id, remove gone annotations, add new ones, move changed coordinates.
- Delegate (`NSObject(), MKMapViewDelegateProtocol`):
  - `viewForAnnotation` → a reused `MKMarkerAnnotationView` with `canShowCallout = false`, `titleVisibility = hidden`, `accessibilityLabel` = the marker's label;
  - `didSelectAnnotationView` → id → callback, then `deselectAnnotation`;
  - `regionDidChangeAnimated` → `region.useContents { }` → `MapViewport.fromCenterSpan`; `null` → `logger.warn` (structured, no coordinates).
  - The last two carry `@ObjCSignatureOverride`, because didSelect/didDeselect and regionWill/regionDid share Kotlin signatures.
- Koin: `single<MapHost> { MapKitMapHost(logger = get()) }`. Xcode: `OTHER_LDFLAGS = $(inherited) -framework MapKit` in `iosApp/Configuration/Config.xcconfig` (the project-level base of all four configurations; the target's `$(inherited) -ObjC` picks it up).

**Tests (`commonTest`)**
- `MapViewportTest`: an ordinary span; clamping at the poles; a crossing at +180 and at −180 (`west > east`); exactly 180 kept; span ≥ 360 → the whole world; extreme spans (lat 400, negative) clamped; non-finite → `null`.
- `MapCameraTest`: zoom 0 at 256 pt → 360°; each zoom step halves the span; `latSpan = lngSpan × cos(lat)`; invalid camera throws.
- `MapViewModelTest`: initial state; `ViewportChanged` stores it, and an equal viewport leaves the same state instance; `MarkerTapped` stores the id.
- Platform hosts are SDK rendering and not unit-testable; they are proven by compilation (Android locally, iOS in CI) and the manual checks.

**Acceptance → proof:** 1 → manual (test plan) + compilation on both platforms; 2–3 → compilation here, on-device in -03's acceptance and the EPIC-01-03 test plan (the ROADMAP -03 line says so); 4 → `MapViewportTest` (shared logic both hosts use on iOS; Google's bounds on Android) + manual; 5 → `MapViewModelTest`; 6 → `MapViewportTest`, `MapCameraTest`; 7 → verify + CI.

**Parity:** both hosts ship in this PR; the same `MapScreen` drives both.

**Windows verification:** `scripts/verify.sh --full` (detekt, host tests incl. Konsist, both Android flavors, lint, backend, secret scan). iOS compile/link/xcodebuild only in CI; I read the iOS job log before any iOS change.
