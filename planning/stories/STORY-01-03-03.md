# STORY-01-03-03: Map data and filters

Status: Done   Epic: EPIC-01-03   Features: MAP-01, MAP-02, MAP-03, PRIV-01   ADRs: ADR-0019, ADR-0020, ADR-0022, ADR-0004

## Goal
The map shows real farts. Panning loads the markers of the visible area from Firestore, and the user switches between Mine / Followers / Everyone; the choice is remembered. Loading, empty, error (with retry) and offline (cached markers) are visible, and `map_viewed` / `marker_opened` are tracked. It also proves on device what STORY-01-03-02 only compiled: markers, taps and the screen-reader label.

## Scope
- **In:**
  - **Viewport → geohash cover, `core/domain/location/GeohashCover.kt`:** the finest precision (6 down to 1) whose cell cover of the viewport has at most 8 cells; antimeridian views are split in two; `null` when even precision 1 needs more (the world-scale view).
  - **Map domain, `feature/map/domain`:** `MapFart` (id, author uid, fuzzed lat/lng, flavor level, event time, visibility), `MapQuery(source, area)` with `MapSource.Public` / `MapSource.Mine(uid)` and `MapArea.Cells(prefixes)` / `MapArea.World`, `MapFartsUpdate.Loaded(farts, isFromCache)` / `Failed(error)`, and `MapFartRepository.observeMapFarts(query): Flow<MapFartsUpdate>`.
  - **Filter, `core/domain/map/MapFilter.kt`:** MINE / FOLLOWERS / EVERYONE (wire names; unknown → EVERYONE). `PreferencesRepository.mapFilter()` / `setMapFilter()` on the `map_filter_last_selected` key (LocalData.md §5, device-scoped).
  - **Firestore, `firebaseData/.../firebase/map/FirestoreMapFartRepository.kt`:** one listener per cell prefix (`coarse_location_key >= p && < p + "~"`, limit 50), or one world listener (limit 200), with `includeMetadataChanges` for `isFromCache`; results merged and de-duplicated by id. Public: `visibility_mode == PUBLIC && is_hidden == false && is_removed == false`. Mine: `author_user_id == uid && is_removed == false`. Failures → `Failed(typed error)` + a structured log. A read-projection DTO with defaults; unknown visibility → PRIVATE.
  - **Indexes, `backend/firestore.indexes.json`:** (visibility_mode, is_hidden, is_removed, coarse_location_key) and (author_user_id, is_removed, coarse_location_key).
  - **Rules tests** for the exact query shapes the app sends (range + limit, world + limit), and their denied neighbours. The rules themselves don't change.
  - **`MapViewModel`:** filter (restored, persisted on change), the query pipeline (`flatMapLatest`, re-subscribed only when the cover, source, uid or retry count changes), status Loading / Ready(isFromCache) / Failed(error), Retry, `map_viewed` and `marker_opened`.
  - **`MapScreen`:** filter row (Mine / Followers / Everyone) over the map, a loading indicator over the base map, the empty card (humorous, nudges to log), the Followers card (humorous "coming soon", ADR-0020), the error card with Retry, the offline chip; markers built from `MapFart` with a voice-y accessibility label.
  - **Analytics:** `AnalyticsEvent.MapViewed(markerCount, filter)` (sends the bucket) and `AnalyticsEvent.MarkerOpened(isOwn, source)` (Observability.md §11).
- **Out:**
  - The marker detail sheet (EPIC-01-05); a tap is recorded and tracked only.
  - Block filtering of PUBLIC markers: blocks ship with EPIC-01-05 (rules don't block-filter PUBLIC reads, DataContracts §5.2; the client hides blocked authors then).
  - The owner's precise pin for their own farts and the pending-write marker style (EPIC-01-04, which writes farts).
  - The FAB, overlay app bar, flavor-styled markers and the marker drop animation (EPIC-01-04 / the map design pass).
  - Device location and "center on me" (-04).

## Acceptance
1. Given a viewport, `GeohashCover.cover` returns the finest precision's cells (≤ 8) that cover it, including a view across the antimeridian (both sides), and `null` for a world-scale view. Unit-tested, including the cell count bound and that every corner and the center of the viewport fall in a returned cell.
2. Given the Everyone filter and a camera at rest, the map subscribes to the PUBLIC, not-hidden, not-removed farts in the viewport's cover and shows them as markers at their fuzzed coordinates; panning within the same cover doesn't re-subscribe, and panning to a new cover does (VM test with a fake repository; the Firestore listener on device in the test plan with seeded farts).
3. Given the Mine filter, the map shows only the user's own non-removed farts (including hidden ones), queried by `author_user_id == uid`. Given Followers, no query runs and the humorous Followers card shows (ADR-0020).
4. The selected filter is saved to `map_filter_last_selected` and restored when the Map opens again (also after an app restart); the default is Everyone, and an unknown stored value reads as Everyone.
5. States: while a query for a new area is loading, the base map stays visible with a loading indicator and the markers of the same filter stay; switching the filter (or the user) clears the markers at once, so another filter's markers never show under the new one. Only farts inside the viewport count and render. An empty result shows the empty card; a failure shows the error card, and Retry re-subscribes; a result served from the cache shows the offline chip with the cached markers. No query starts before the saved filter is restored.
6. Rules (emulator): the app's public range query (with limit) and world query succeed for a signed-in user; the Mine range and world queries succeed for the owner; a range query missing `is_hidden` or `is_removed`, a FOLLOWERS query, another user's Mine query, and a signed-out query fail. A backend unit test asserts `firestore.indexes.json` holds the two composite indexes in query order. Precise coordinates never appear: the map reads only public docs.
7. Mapping: a fart doc maps to `MapFart` field by field; an unknown `visibility_mode` maps to PRIVATE (regression test); missing fields decode to defaults instead of crashing.
8. Analytics: `map_viewed` fires once each time the Map tab is shown (the tab's content enters composition; `NavHost` composes only the current tab), after its first result, with `marker_count_bucket` (`0`, `1_9`, `10_49`, `50_plus`) and `filter` (`mine` / `followers` / `everyone`); `marker_opened` fires on a marker tap with `is_own` and `source = map` (TASK-07 updates the Observability §11 row: the tap that will open the sheet; a tap on an id no longer in State is not tracked). No ids or coordinates in either.
9. **Carried from -02, on device (test plan):** seeded markers render on Android and iOS and disappear when the filter or area excludes them; a tap reports the id, twice on the same marker too; TalkBack / VoiceOver read the marker label.
10. `scripts/verify.sh --full` is green; CI (Android, iOS link + xcodebuild, backend incl. emulator rules tests, secret scan) is green.

## Decisions
- **Followers runs no query.** ADR-0020: the filter is present in Phase 1 and shows a humorous empty state until SOCIAL-03. FOLLOWERS reads would also need the per-author follower feed (DataContracts §5.2), which is Phase 2.
- **Query shape = the rules' list shapes.** Public: the three equality constraints the rules require, plus the geohash range. Mine: `author_user_id == uid` plus `is_removed == false` (a soft-deleted fart is gone from the map; hidden ones stay visible to their author, matching `canReadFart`). No rules change.
- **Cover sizing.** Up to 8 listeners per view, 50 docs each (400 markers at most), at the finest precision that fits. Beyond precision 1 (a view wider than about two 45° cells) one world query with limit 200 replaces the cells. Firestore orders a range query by key, so a dense cell shows its first 50 docs by geohash, not the newest; fine for Phase 1 density (cold start), and revisited with heatmaps (MAP-04, Phase 2). Source: simplest within the rules' allowed shapes; the 8/50/200 values are implementation details.
- **Re-subscribe only on a new cover.** The VM keys the subscription on (cover, source, uid, retry count) with `distinctUntilChanged`, so small pans cost nothing.
- **Own farts use the fuzzed point too.** `MapScreen.md` allows the owner's precise pin; reading it means one `private/location` get per own fart. The safer and simpler choice is the public point for everyone in this story; EPIC-01-04 (which writes the precise doc and shows the just-logged marker) decides whether to add it.
- **Read projection DTO.** The map reads a subset DTO (fields it needs, all with defaults; unknown keys ignored). The full 1:1 fart DTO arrives with the write path in EPIC-01-04 (DataContracts §7); there is no write here, so there's nothing to round-trip yet. The mapper test covers every projected field and the visibility regression.
- **Accessibility label without the username.** `DesignSpecification.md` wants "Fart by [username], [flavor], [time ago]". The public fart doc has no display name, and one profile read per marker is too heavy for the map. The label is "A level-3 fart, 2 hours ago" ("Your level-3 fart, …" for your own); the username joins when the detail sheet loads the author (EPIC-01-05).
- **Offline indication.** `isFromCache` → a subtle chip, never an error (LocalData §4, `Architecture.md` §8). Firestore may raise a cache snapshot before the server one, so the chip can flash briefly on a first load; accepted for Phase 1, revisited in the design pass.
- **`map_viewed` timing.** The route sends `MapAction.Shown` when it enters composition; the VM tracks once the first result after it is ready (immediately for Followers), so `marker_count_bucket` is real. An Android configuration change re-enters composition and can count again; accepted (activity recreation is rare with Compose and the shell's config).
- **`marker_opened` on tap (plan review).** Observability §11 tied it to the detail sheet opening; the sheet opens on that same tap in EPIC-01-05, so tracking the tap now keeps the funnel continuous. TASK-07 edits the §11 "When" column to say so, and EPIC-01-05 keeps a single call where the sheet opens (no double-fire).
- **Markers follow the filter (plan review).** The VM keeps markers across a re-query only when the source and uid are unchanged (a pan); a filter or user change clears them before the new query. The pipeline starts only after the saved filter is read, so a Mine user never sees an Everyone flash.
- **Only visible farts count (plan review).** A cover cell can be larger than the view, and the 50-doc limit can fill with docs outside it. The VM keeps the raw result privately and puts only the farts inside the viewport (antimeridian-aware) into State, so the empty card and `marker_count_bucket` reflect what is on screen. A truncated dense cell can still show the empty card for a zoomed-in corner of it; accepted until MAP-04 (Phase 2).
- **Indexes are checked by a unit test** (plan review): the emulator doesn't enforce composite indexes, so `test/indexes.test.ts` asserts the two field lists. CI deploys them to dev on merge (`deploy-backend.yml`).
- **GitLive decoding of a subset DTO.** GitLive decodes by the serial descriptor and ignores document keys the DTO doesn't declare (the same way `FirestoreAccountRepository` reads its fields). The first step of TASK-03 is a compile of the query/metadata calls on Android; iOS follows in CI.
- **Plan review round 2 notes.** A tap on an id that has left State is stored but not tracked (no `is_own` to report). `map_viewed` sent while already Ready uses the current State's filter and farts; after a tab return the VM (kept by the back stack) still holds the current filter, so that is accurate. Everyone is PUBLIC only, so your own FOLLOWERS / PRIVATE farts show under Mine only (rules shape; intentional). One failing cell listener fails the whole view (error card + Retry); accepted, since the cells share one cause in practice (network, rules, missing index).
- **PR review fixes.**
  - When any listener hits its limit (`isTruncated`), an empty view shows "Too much wind out here, zoom in" in place of the empty card.
  - A pan to a new cover keeps `Ready` (and the offline chip) until the new result arrives. `Loading` shows only on a filter or user change and on Retry.
  - A filter or user change clears `selectedMarkerId`.
  - A tap on an id that has left State is ignored. This supersedes the round-2 note "stored but not tracked".
- **No session, no query.** The Map tab only exists in an Active session (the start destination comes from the session), so "Loading until Active" can't strand a user; when the session leaves Active the VM drops the subscription with the farts.
- **`map_filter_last_selected` is device-scoped.** LocalData §7 lists the user-scoped keys (draft, nudges, offers, last visibility); the filter isn't one and leaks nothing about an account.
- **Pending marker style deferred.** LocalData §4's pending style needs own writes, which start in EPIC-01-04.

## Plan
**`shared/src/commonMain`**
- `core/domain/location/GeohashCover.kt`: `object GeohashCover { const val MAX_CELLS = 8; fun cover(viewport: MapViewport, maxCells: Int = MAX_CELLS): List<String>? }`. Per precision p (6 → 1): latBits = 5p/2, lngBits = 5p − latBits, cell size h = 180/2^latBits, w = 360/2^lngBits. Lng intervals: `[west, east]`, or `[west, 180]` + `[-180, east]` when crossing. Cell index ranges by `floor((x + offset)/size)` clamped to the grid; count = rows × Σ columns. First p with count ≤ maxCells → enumerate the cells (`Geohash.encode` of each cell's center), return sorted and distinct. None → `null`.
- `core/domain/map/MapFilter.kt`: `enum class MapFilter(val wireName) { MINE, FOLLOWERS, EVERYONE }` + `fromWire` (unknown/null → EVERYONE).
- `core/domain/preferences/PreferencesRepository.kt`: `suspend fun mapFilter(): MapFilter`, `suspend fun setMapFilter(filter): AppResult<Unit>`. `DataStorePreferencesRepository`: key `map_filter_last_selected` (device-scoped), guarded read → EVERYONE on a storage error.
- `feature/map/domain/MapFarts.kt`: `MapFart`, `MapSource`, `MapArea`, `MapQuery`, `MapFartsUpdate`, `interface MapFartRepository { fun observeMapFarts(query: MapQuery): Flow<MapFartsUpdate> }` (KDoc: never throws; a failure is a `Failed` emission that ends the flow).
- `core/observability/Analytics.kt`: `MapViewed(markerCount: Int, filter: MapFilter)` → params `marker_count_bucket`, `filter` (lowercase wire); `MarkerOpened(isOwn: Boolean, source: MarkerSource)` with `enum MarkerSource { MAP("map") }`. Bucket function tested.
- `feature/map/presentation/MapState.kt`: `MapState(camera, viewport, selectedMarkerId, filter = EVERYONE, farts: List<MapFart> = emptyList(), status: MapDataStatus = Loading, nowEpochMs: Long = 0)`, `sealed interface MapDataStatus { Loading; Ready(isFromCache); Failed(error) }`; actions `CameraIdle`, `MarkerTapped`, `FilterSelected(filter)`, `Retry`, `Shown`. `markers` disappears from State (the screen builds them from `farts`).
- `feature/map/presentation/MarkerLabel.kt`: `fartAge(nowMs, thenMs): FartAge(unit = JUST_NOW/MINUTES/HOURS/DAYS, count)` (pure, tested) and `@Composable fun MapFart.markerLabel(uid, now)` using plural string resources.

Init: read the saved filter **first**, then collect `combine(request, sessions.session.uid)` → `MapRequest(area, filter, uid, attempt)` `distinctUntilChanged` → `flatMapLatest` (FOLLOWERS → `flowOf(Loaded(empty, false))`; otherwise `observeMapFarts(...)` with `onStart { status = Loading }`) → reduce: Loaded → raw farts kept privately, State gets the ones inside the viewport + `Ready(isFromCache)` + now; Failed → `Failed(error)`. When `(filter, uid)` differs from the previous request, the raw list and State farts are cleared before subscribing (plan review). A `CameraIdle` with the same cover re-filters the raw list against the new viewport. No query until the first viewport and an Active session; leaving Active clears farts. `FilterSelected` sets state, persists (a failed write is already logged by the repository and the in-memory choice still applies), re-keys. `Retry` bumps attempt. `Shown` → pending flag; tracked on the next Ready (or immediately if Ready). `MarkerTapped` stores the id and tracks `MarkerOpened(isOwn = fart.authorUid == uid, MAP)`.
