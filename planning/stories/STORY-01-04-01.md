# STORY-01-04-01: Fart create path (client batch + server location re-validation)

Status: Done   Epic: EPIC-01-04   Features: CREATE-01, CREATE-03.3, PRIV-01, PRIV-02   ADRs: ADR-0019, ADR-0022, ADR-0023

## Goal
The app can hand one fart to Firestore the way the contracts require: a single batch with the public doc (fuzzed geohash-6 point) and the owner-only `private/location` (precise point), launched in `AppWriteScope` and never awaited, so it works offline. The backend makes sure a public point can't drift from the private one: rules require the private location in the creating batch, and `onFartCreated` recomputes the public fields from it and overwrites them if they differ. The Log Fart screen (STORY-01-04-02) only has to call `FartRepository.createFart`.

## Scope
- **In:**
  - **`shared` `core/domain/fart`:**
    - `NewFart` (the CREATE-03.3 fields without `voice_url`, which is Phase 4): precise `lat`/`lng`, `timestampEpochMs`, `avatarId`, `flavorLevel`, `intensityValue`, `descriptionText?`, `soundId?`, `visibility`.
    - `validateNewFart(NewFart): AppError.ValidationFailed?`: the same limits the rules enforce (lat/lng range and finite, flavor 1..5, intensity 0..1 and finite, avatar not blank, description ≤ 500 characters, sound id not blank when present). Client validation comes first because a rejection after a process restart isn't reported (`LocalData.md` §3.5).
    - `FartRepository.createFart(uid, fart): AppResult<String>` returns the client-generated fart id once the batch is handed off.
  - **`firebaseData` `firebase/fart`:**
    - `NewFartDto` (exactly the rules' create field set, no defaults so every field is encoded) and `PrivateLocationDto`.
    - pure `buildFartWrite(fartId, uid, fart): FartWrite(public, private)`: fuzzed fields from `LocationFuzzer.project(fartId, lat, lng)`, counters 0, `reaction_breakdown` empty, `is_hidden`/`is_removed` false, server timestamps; a blank description is sent as null.
    - `FirestoreFartRepository`: validates, generates the id (`collection("farts").document`), builds the write, launches one `batch().set(public).set(private).commit()` in `AppWriteScope` with op `fart.create`, returns `Success(id)` at once. Koin binding.
  - **Rules (`backend/firestore.rules`):**
    - a fart create requires `existsAfter(farts/{id}/private/location)`, so the private point always lands in the same batch;
    - `private/location` may only be **created**, only in the batch that creates its fart (`!exists(fart)` before, `getAfter(fart)` by the caller and not removed); `update` is denied (moving a fart is not in Phase 1; edit is Phase 2, CREATE-09).
  - **`onFartCreated` (`backend/functions/src/triggers/fartCreated.ts`):** inside `runOnce`, reads `private/location`, recomputes with `projectPublicLocation`, and on any mismatch overwrites `public_lat`, `public_lng`, `coarse_location_key` and `updated_at`. Logs `fart_projection_checked` with `{ fartId, corrected }` only, never coordinates. A missing or invalid private location (only possible through the Admin SDK) is logged as a warning and nothing is written. Added to `PROD_FUNCTIONS`, since it now does real work.
  - **Docs:** `DataContracts.md` §3.2.1, §5.8 and §9 (create-only private location, the trigger), ROADMAP split of EPIC-01-04, STATE.
- **Out:**
  - Any UI, the location fix and permission, the visibility selector, `fart_logged` analytics (STORY-01-04-02).
  - The read DTO of a full fart, pending markers on the map (STORY-01-04-02), drafts (-04), delete and the private-location purge on removal (-05).
  - Rewarded-token consumption for paid cosmetics (EPIC-01-06; the rules already accept free or entitled items only).

## Acceptance
1. Given a valid `NewFart`, when `buildFartWrite(id, uid, fart)` runs, then the public DTO carries exactly the rules' create field set; `fart_id` = id, `author_user_id` = uid; `public_lat`/`public_lng`/`coarse_location_key` equal `LocationFuzzer.project(id, lat, lng)` and differ from the precise point; every user field (timestamp, avatar, flavor, intensity, description, sound, visibility) is copied unchanged; counters are 0, flags false, timestamps are server timestamps; the private DTO holds the precise `lat`/`lng`.
2. **Visibility regression (PoC failure):** for each of PUBLIC, FOLLOWERS and PRIVATE, the public DTO's `visibility_mode` is that value's wire name.
3. Given an invalid `NewFart` (lat 91, lng −181, NaN lat, flavor 0 or 6, intensity −0.1, 1.1 or NaN, blank avatar, a 501-character or 251-emoji description (UTF-16 units, as the rules count), a blank sound id), `validateNewFart` returns `ValidationFailed` naming the field; a 500-character or 250-emoji description, `soundId` null and intensity 0 and 1 pass.
4. Rules (emulator):
   - the batch fart + `private/location` by the author is allowed (author, anonymous author);
   - a fart created without its `private/location` in the same batch is denied;
   - creating `private/location` for an already existing fart is denied, even by the author;
   - updating `private/location` is denied;
   - every earlier allowed and denied fart case still holds in batch form (signed-out, other user, mismatched id, precise or unknown keys, invalid values, paid cosmetics, PUBLIC for adults only).
5. `onFartCreated` handler (emulator):
   - a fart whose public fields don't match its private location gets them overwritten with `projectPublicLocation`'s result and `updated_at` changes;
   - a matching fart is left untouched (no write);
   - the same event id runs once;
   - a fart without `private/location`, or an event whose fart doc is gone, is not modified, is logged as an error, and the handler doesn't throw;
   - the log calls carry no coordinate fields.
6. `scripts/verify.sh --full` is green, and CI (Android, iOS, backend incl. emulator suites, secret scan) is green.

## Decisions
- **How EPIC-01-04 is split** (`--cross-epics`, autopilot §0.4). "Log Fart: quick log + detailed log, drafts, offline, delete, visibility default, account-link nudge" (CREATE-01–07, CREATE-09, PRIV-01, ADR-0018 §3):
  - **-01** (this story): the create path, client and server, without UI. It comes first so the screen stories only call one repository method, and the server guarantee (ADR-0019 §4) exists before real user farts do.
  - **-02**: quick log. A map action opens the Log Fart screen: the location step (current device fix shown as a coarse thumbnail, "Adjust location" pin picker, a pin required when there's no fix, and the "move the pin" hint for an approximate fix per ADR-0026), the visibility selector with the ADR-0023 default and "your exact spot stays private", the free starter avatar and the field defaults (flavor 3, intensity 0.5, now), "Let It Rip", `UPLOADING` / `SUCCESS` / `FAILED` / `OFFLINE` states, the new marker on the map with the pending style, the offline toast, `last_visibility_mode` saved, `fart_logged` analytics.
  - **-03**: detailed fields on the same screen: date/time picker, avatar picker (free and owned), flavor stepper, intensity slider, description with rotating placeholders and the 280 counter, sound picker (free and owned, at least 3 free), the locked voice row with its informational sheet. Locked paid items and the unlock sheet stay in EPIC-01-06 (CREATE-03.2 says a locked item always opens the Buy / Watch-ad sheet, and that sheet doesn't exist before EPIC-01-06; until then the pickers list free and owned items only).
  - **-04**: drafts: `log_draft` in DataStore, survives process death, restored on reopen, cleared on hand-off, kept on failure; back from a dirty draft asks keep or discard.
  - **-05**: delete own fart (CREATE-09): a minimal owner action on the user's own marker (the full detail sheet is EPIC-01-05), the soft delete `USER_DELETED`, and the server purge of `private/location` on removal.
  - **-06**: the one-time account-link nudge after the first successful log for a guest (ADR-0018 §3, `account_link_nudge_shown_at`, reuses `SessionRepository.linkGoogle`).
- **Fine location for the precise point (STATE asked EPIC-01-04 to decide): Proposed ADR-0026, listed in STATE "Pending owner decisions" (plan review).**
  - Recommended: Android stays on `ACCESS_COARSE_LOCATION`. When the fix is approximate, the location step says "Roughly here. Move the pin if this isn't right." and offers the pin picker (CREATE-03.1 step 1). iOS is unchanged.
  - Alternative: a fine-location ask in context on Log Fart.
  - -02 must build the approximate-fix hint and keep the permission behind `LocationProvider`. That way -02 ships with today's permissions and doesn't depend on the ADR, and accepting the alternative later changes only the platform implementation, the manifest and the ask.
  - This story doesn't touch location permissions.
- **Package `core/domain/fart`.** Both the Log Fart feature (create) and the map (delete in -05) write farts, and features don't import each other.
- **Rules tightened, not widened.** Requiring the private location in the creating batch and making it create-only follows ADR-0019 §2/§4 directly: without it a client bug could publish a precise point as the "public" one with no private doc to re-validate against. Moving a fart isn't a Phase 1 feature (CREATE-09 edit is Phase 2), so no `update` is needed. Source: ADR-0019, `DataContracts.md` §5.8, tie-break "safer for privacy".
- **Trigger on the fart, not on the private doc.** With create-only private locations in the same batch, the fart's create event always sees its private location, so one trigger (`onFartCreated`, already deployed to dev) is enough. It moves to prod now because it does real work (STORY-01-01-04 kept it dev-only until then).
- **A missing or invalid private location (or a missing fart) in the trigger** is logged with `logError` (`fart_projection_skipped`, so it reaches error reporting) and left alone. Rules make it impossible for clients, so only Admin SDK writes could cause it. Hiding the fart would be a moderation action the docs don't define. **Transient failures** (a read or update throws) are rethrown: `runOnce` releases the lease and the trigger is deployed with `retry: true`, so the check isn't silently lost. The window between commit and trigger is accepted by ADR-0019 §4.
- **ADR-0019 §2 is narrowed, not reversed.** "Readable and writable by the author only" still holds; the author may now only write the private location once, in the creating batch. `DataContracts.md` §5.8 and §9 say so.
- **Description length.** The rules' `string.size()` and Kotlin's `String.length` may count emoji differently.
  - The first plan was to count code points. CI showed the rules deny 500 emoji, so per the fallback the client now matches the rules (the server is authoritative).
  - `validateNewFart` counts UTF-16 code units (`String.length`), and the emulator test pins 250 emoji as allowed and 251 as denied.
  - `DataContracts.md` §4.11 names the unit.
  - Carried to -03: the 280 soft-limit counter must use the same unit, or show the hard limit, so a long emoji caption isn't rejected after the user typed it.
- **Known window (security review, accepted by ADR-0019 §4).** Rules can't compute the fuzz. A modified client could publish its own exact point until `onFartCreated` corrects it, or longer while the trigger is down. Only the author's own location is exposed. Closing the window (for example, hiding unchecked farts from list queries) is a bigger change and not in this story.
- **Redaction.** `public_lat`/`public_lng` join the forbidden log keys in `lib/log.ts`. They are fuzzed, but they are still coordinates (`DataContracts.md` §6.4).
- **`createFart(uid, …)` takes the uid** like `ProfileRepository.createProfile`: the caller (the ViewModel in -02) reads the active session; the repository stays free of session state.
- **A blank description is sent as null**, so the doc never holds an empty caption. Not trimmed otherwise (emoji and spacing are the user's).
