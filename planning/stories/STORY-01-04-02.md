# STORY-01-04-02: Quick log (Log Fart screen, location step, visibility, "Let It Rip")

Status: Done   Epic: EPIC-01-04   Features: CREATE-01, CREATE-02, CREATE-03.1 (steps 1, 9, 10), PRIV-01, PRIV-02   ADRs: ADR-0019, ADR-0022, ADR-0023 (ADR-0026 Proposed, not depended on)

## Goal
From the map, a user taps the log button, sees where the fart will land (their device fix, or a pin they place), sees and can change who will see it, and taps "Let It Rip". The screen closes, the map moves to the new marker, which shows the pending style until the server has it. Offline it still works, with the "saved locally" message.

## Scope
- **In:**
  - **Map entry:** a "Log a fart" FAB on the Map tab opens the Log Fart screen (a typed route in the Map tab's stack; the bottom bar is hidden there). The map's current camera travels as the route's start camera for the pin picker.
  - **Location step (CREATE-03.1 step 1):**
    - permission already granted → a fresh fix at screen open, with the cached fix as a fallback;
    - not granted → "Location unavailable" with a "Use my location" button (the same in-context ask as "center on me") and "Adjust location";
    - blocked → the same, plus "Open settings";
    - a resolved point is shown as a small non-interactive map thumbnail at neighbourhood zoom with a centre pin; never coordinate text (PRIV-02);
    - an approximate device fix (Android coarse, iOS reduced accuracy or a fix worse than 200 m) shows "Roughly here. Move the pin if this isn't right." Submitting is never blocked by it (ADR-0026 §2, which -02 builds either way);
    - "Adjust location" opens a full-screen pin picker: a native map with a fixed centre pin, "Use this spot" and "Cancel". It opens at the resolved point, otherwise at the map's camera;
    - "Let It Rip" stays disabled until a point is resolved (fix or pin).
  - **Visibility (step 9, PRIV-01):** the options from `allowedVisibilities(ageBand)`, preselected with `defaultVisibility(lastUsed, ageBand)`, with the note "Your exact spot stays private." `last_visibility_mode` is saved after a successful hand-off.
  - **Defaults for the other fields:** now (at screen open), the first free starter avatar, flavor 3, intensity 0.5, no description, no sound. -03 adds the pickers.
  - **Submit (step 10):** `DRAFT` → `UPLOADING` → `SUCCESS` or `OFFLINE` (the hand-off succeeded; offline when `NetworkStatus` says there's no connection), or `FAILED` (a typed error with "Try again", fields kept). On success the screen closes, the map moves to the new marker's public point and a snackbar says "Logged. The world felt it." or "Saved locally — will post when you're back online."
  - **Pending marker style:** `MapFart.isPending` from `hasPendingWrites`, drawn at half opacity on both hosts and announced as "posting" to screen readers. Documented in `MapScreen.md`.
  - **Server rejection after hand-off:** one app-level collector of `PendingWriteMonitor` in the main shell shows "We couldn't post that one." for `fart.*` operations.
  - **New platform capability `NetworkStatus`** (`isOnline()`): `ConnectivityManager` on Android, `NWPathMonitor` on iOS.
  - **Analytics:** `log_started` (`entry` = `fab`) and `log_submitted` (`visibility`, `has_description`, `has_sound`, `avatar_is_free`, `offline`) from `Observability.md` §11.
- **Out:**
  - Date/time, avatar, flavor, intensity, description, sound pickers and the locked voice row (-03).
  - `log_draft`, keep-or-discard on back, draft kept on failure across process death (-04); `log_abandoned` (needs the draft's `step_reached`, -04).
  - `marker_appeared` (needs a render callback from the hosts; tracked as a follow-up in Decisions).
  - A marker-drop animation (visual polish, revisited after Phase 1 implementation, STATE "Decided").
  - Fine location (ADR-0026 option A, if accepted, changes only the provider, manifest and ask).

## Acceptance
1. **Visibility default.** Given an Active ADULT with no saved choice, the screen preselects PUBLIC and offers all three; a TEEN gets FOLLOWERS and is offered FOLLOWERS and PRIVATE only; a saved choice still allowed wins (PRIVATE for a teen); a saved PUBLIC for a teen falls back to FOLLOWERS.
2. **Location with permission.** Given permission GRANTED and a fix, the location step resolves to that point (`LocationStep.Resolved`, source DEVICE) without asking. An approximate fix sets the hint flag; a precise one doesn't. If the fresh fix fails or takes longer than 12 s, the cached fix is used; if there's neither, the step is `Missing(UNAVAILABLE)` (or `SERVICES_OFF`). `isApproximateFix` is true for reduced accuracy, an unknown or negative accuracy, or more than 200 m.
3. **Location without permission.** Given NOT_DETERMINED, opening the screen does not ask; the step is `Missing(NEEDS_PERMISSION)`. "Use my location" asks once; GRANTED then looks up the fix; DENIED keeps `Missing(NEEDS_PERMISSION)`; BLOCKED shows `Missing(BLOCKED)` and "Open settings" opens the app settings.
4. **Pin picker.** "Adjust location" opens the picker at the resolved point (pin zoom), or at the route's start camera when nothing is resolved. Camera moves update the picker centre; "Use this spot" resolves the step to that centre (source PIN, no approximate hint) and closes the picker; "Cancel" closes it and keeps the previous step.
5. **Submit gate and back.** "Let It Rip" is disabled while the step isn't resolved and while `UPLOADING`. "Adjust location" is available while locating. Back with the picker open closes only the picker; back while `UPLOADING` does nothing; otherwise back closes the screen (`Closed`).
6. **Hand-off.** Given a resolved point and visibility V, "Let It Rip" calls `createFart(uid, fart)` once with the resolved point, V, the start time, `avatar_free_bean`, flavor 3, intensity 0.5, no description and no sound. `log_submitted` is tracked on the tap with the right params. On `Success(id)`: status `SUCCESS` (online) or `OFFLINE` (no network); `last_visibility_mode` = V; one `Finished` event whose `LoggedFart` carries the id, V, the offline flag and `LocationFuzzer.project(id, …)`'s public point (never the precise point).
7. **Visibility regression.** For each of PUBLIC, FOLLOWERS, PRIVATE selected, the `NewFart` handed to the repository carries that value.
8. **Failure.** Given `createFart` returns `Failure(e)`, status is `FAILED` with `e`, the visibility isn't saved, no `Finished` event, and every field is kept; "Try again" submits again. A session that isn't Active fails with `AuthExpired` without calling the repository.
9. **Map after a log.** Given a `LoggedFart`, the map moves the camera to its public point. When the current filter wouldn't show it (Everyone with non-PUBLIC, or Followers), the filter switches to Mine for this session without saving the preference.
10. **Pending style.** A map doc with `hasPendingWrites` maps to `MapFart.isPending = true`, which becomes `MapMarker.isPending` with a label ending in ", posting" (pure helper, unit-tested). Both hosts draw a pending marker at half opacity (device check by the owner; CI only compiles iOS).
11. **Rejection.** A `WriteRejected` with op `fart.create` makes the main shell show "We couldn't post that one."; other ops show nothing (they're logged already).
12. **Analytics.** `log_started` with `entry=fab` once per screen open; `log_submitted` once per gated submit tap; params match `Observability.md` §11 and carry no coordinates or text.
13. `scripts/verify.sh --full` is green, and CI (Android, iOS, backend, secret scan) is green.

## Decisions
- **Analytics names.** ROADMAP said `fart_logged`, which no contract defines. `Observability.md` §11 (higher authority than the ROADMAP line) defines `log_started` and `log_submitted`, so those are used and the ROADMAP line is fixed. `log_abandoned` moves to -04 (its `step_reached` belongs with the draft), and `marker_appeared` is a follow-up: it needs a "rendered" callback from both map hosts, which is more than this story needs. Source: WorkingAgreement §1, Observability.md §11.
- **Location permission on Log Fart.** Opening the screen never prompts. Without permission, the step offers "Use my location" (an explicit tap, the same in-context ask as "center on me") and the pin. Growth.md §2 and issue #25 say "ask at first map use, never at launch; the first 'center on me' tap". An auto-prompt at screen open would add a second first-ask point the owner didn't choose. Source: Growth.md §2, issue #25, tie-break "safer for privacy".
- **What "approximate" means.** Android: always, since only `ACCESS_COARSE_LOCATION` is held (STORY-01-03-04). iOS: `accuracyAuthorization` is reduced, or `horizontalAccuracy` is negative or above 200 m. The flag lives on `DeviceLocation` (default false), so ADR-0026 option A would only change the Android provider. Source: ADR-0026 §2–§3, STORY-01-04-01 Decisions.
- **The thumbnail is a non-interactive native map** at zoom 13 with a centre pin drawn by Compose. `MapHost.Content` gains an `interactive` flag (gestures off) instead of a second capability. Source: CREATE-03.1 step 1, ADR-0008 (one map capability).
- **Pin picker = centre-pin map.** The pin stays in the middle and the user moves the map; the chosen point is the camera centre `onCameraIdle` reports. No draggable-marker API is added to `MapHost`. It is a full-screen overlay inside the Log Fart screen, not a dialog, so the native map view isn't hosted in a separate window. Source: CREATE-03.1 step 1 ("drag a pin"; same result, simpler, no new host API).
- **SUCCESS vs OFFLINE.** The write is never awaited (ADR-0022). A new `NetworkStatus.isOnline()` decides which message to show at hand-off. It changes only the copy and the `offline` analytics param, so "unknown" counts as online. iOS keeps one `NWPathMonitor` running and reads its last status. Android reads `ConnectivityManager`'s active network capabilities (`ACCESS_NETWORK_STATE`, a normal permission). Source: create.md step 10, Observability.md (`offline` param), kotlin-shared rules (an SDK capability goes behind an interface in `core/platform`).
- **Results go back through the main shell.** The Log Fart screen emits `Finished(LoggedFart)`. The shell pops back, shows the snackbar and hands the `LoggedFart` to `MapRoute`, which sends `MapAction.FocusLogged`. Features don't import each other: `LoggedFart` lives in `core/domain/fart`. Source: Architecture layering, kotlin-shared rules (navigation through `core/navigation`).
- **The map moves to the public point, not the precise one.** `LoggedFart` carries `LocationFuzzer.project(id, lat, lng)`, which is where the marker is actually drawn, so the precise point never leaves the Log Fart screen. Source: ADR-0019, tie-break "safer for privacy".
- **Filter after a log.** If the current filter can't show the new fart (Everyone shows PUBLIC only; Followers runs no query until SOCIAL-03), the map switches to Mine for the session without saving `map_filter_last_selected`, so the user sees the marker land and their saved preference is untouched. Source: create.md step 10 ("marker drop at the confirmed location"), LocalData.md §5.
- **Avatar default.** The first free starter avatar (`avatar_free_bean`) until -03's picker. It's always free, so the rules accept it. Source: create.md step 3, `StarterAvatars`.
- **Timestamp.** Taken at screen open (create.md step 2), not at submit.
- **FAILED keeps fields in memory only.** Draft persistence across process death is -04 (ROADMAP split in STORY-01-04-01 Decisions).
- **Rejection surfacing.** `PendingWriteMonitor` has no collector yet. A `MainShellViewModel` collects it while the main shell is shown and surfaces only `fart.*` operations ("We couldn't post that one."). `profile.create` rejections stay log-only, as today. Source: LocalData.md §3 ("one app-level collector should own surfacing"), create.md step 10.
- **Pending style.** Half opacity plus a "posting" suffix on the screen-reader label, so the state isn't carried by colour alone. `MapScreen.md` records it (the screen spec had no definition; STORY-01-03-03 deferred it here). Source: LocalData.md §4, compose-ui rules (accessibility).
- **`log_submitted` fires on the tap** (Observability.md §11: "submit tapped"), once per tap that passes the gate, before the hand-off, with `offline` from `NetworkStatus`. A failed hand-off is logged by the ViewModel (`log_submit_failed`, error category only). Source: Observability.md §11 (plan review, round 1).
- **Back.** System back and the iOS swipe go through Compose Multiplatform's `BackHandler`: with the picker open they close the picker, while `UPLOADING` they do nothing, and otherwise they close the screen without asking. Keep-or-discard is -04. Source: create.md state table ("back navigation disabled"), plan review.
- **Fix timeout.** The ViewModel bounds the fresh fix at 12 s (`withTimeoutOrNull`), then uses the cached fix, then `Missing(UNAVAILABLE)`. "Adjust location" is offered while locating too, so a slow fix never traps the user. Source: create.md step 1, plan review.
- **Behaviour change to create.md step 1, recorded as a tie-break** (WorkingAgreement §6, "safer for privacy"): "auto-detects GPS at screen open" holds when permission is already granted. Otherwise the first-ever log needs one extra tap ("Use my location") or a pin, which slightly slows the 60 s L1 goal for users who never tapped "center on me". The PR says so for the owner.
- **ADR-0026 stays reversible.** The hint string and the `isApproximate` flag are the only places it shows. Option A (fine location) changes only the Android provider and the manifest; option B (a pin required on Android) changes only the submit gate.
- **Privacy implications.** No new data leaves the device: the write path is STORY-01-04-01's. The precise point stays inside the Log Fart ViewModel and the private doc. Analytics carry categories and booleans only. `NetworkStatus` reads connectivity state only. No monetization surface is added; the avatar is free.
