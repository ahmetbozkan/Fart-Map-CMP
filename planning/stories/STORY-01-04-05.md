# STORY-01-04-05: Delete own fart (soft delete + server purge of the precise location)

Status: Done   Epic: EPIC-01-04   Features: CREATE-09 (delete only; edit and preview are Phase 2)   ADRs: ADR-0019, ADR-0020, ADR-0022

## Goal
A user can take back a fart they logged. Tapping their own marker on the map offers "Delete", behind a confirmation. The fart disappears from the map at once (also offline) and is soft-deleted on the server with `removed_reason = USER_DELETED`. The server then removes the owner-only precise location, so nothing precise outlives a deleted fart.

## Scope
- **In:**
  - **`shared` `core/domain/fart`:** `FartRepository.deleteFart(uid, fartId): AppResult<Unit>`. It validates the ids and hands one batch to the app write scope without awaiting it (like `createFart`).
  - **`firebaseData`:** `FirestoreFartRepository.deleteFart`: one `batch().update(fartRef, is_removed = true, removed_reason = "USER_DELETED", updated_at = serverTimestamp)` launched in `AppWriteScope` (op `fart.delete`). The pure field map is a tested function (`buildFartDeleteFields`).
  - **Map presentation:** tapping an **own** marker opens a confirmation dialog (title, body, "Delete" / "Keep it"). Tapping a marker of someone else still only selects it (the detail sheet is EPIC-01-05). The dialog is State (`pendingDeleteId`), so it survives rotation.
  - **Analytics:** `fart_deleted` with `age_bucket` (Observability.md §11).
  - **Backend:** `onFartRemoved` (`onDocumentUpdated` on `farts/{fartId}`). When `is_removed` goes from not-true to true it deletes `farts/{id}/private/location` through the Admin SDK, idempotently (`runOnce` + a delete of a missing doc is a no-op). Added to `PROD_FUNCTIONS`. The rules comment "Purging … is server work" now points at it.
  - **Docs:** `DataContracts.md` §3.2.1 / §9 (purge on removal), `MapScreen.md` (own-marker dialog), `Observability.md`, ROADMAP / STATE.
- **Out:**
  - The detail sheet, reactions, report and block (EPIC-01-05). Delete moves into the sheet there; the dialog is the minimal owner action the split in STORY-01-04-01 promised.
  - Edit, undo, "recently deleted" (Phase 2 / not specified).
  - Purging reactions or comments of a removed fart (none can exist before EPIC-01-05; that epic's story owns it).
  - Profile-list delete (no profile fart list yet).

## Acceptance
1. **Delete write.** The field set of the delete update is exactly `is_removed = true`, `removed_reason = "USER_DELETED"` and `updated_at` = server timestamp (`buildFartDeleteFields`, unit test). A blank uid or fart id returns `Failure(ValidationFailed)` and writes nothing. That `deleteFart` launches the batch in `AppWriteScope` (op `fart.delete`) and returns without awaiting it has the same code shape as `createFart`; it is covered by review and the owner's offline check, since `firebaseData` tests don't run the SDK.
2. **Own marker → dialog.** Given a loaded own marker, `MarkerTapped` sets `pendingDeleteId` and `selectedMarkerId`, and tracks `marker_opened` once. A marker of someone else sets only `selectedMarkerId`.
3. **Confirm.**
   - `ConfirmDelete` clears the dialog and sends `MapEvent.DeleteFart(id)`; the route calls `OwnFartDeleter.delete(id)`, which calls `deleteFart(uid, id)` and tracks `fart_deleted` with `age_bucket` (`13_17` / `18_plus`).
   - On `Failure` (only a blank id, a programming error) the dialog closes and nothing is tracked. A real rejection arrives later through the `PendingWriteMonitor` snackbar.
   - A second `ConfirmDelete` with no pending id sends nothing.
4. **Dismiss.** `DismissDelete` clears the dialog and writes nothing.
5. **Stale target.** If the pending fart leaves the loaded list (a refresh, another filter, a sign-in change) the dialog closes by itself.
6. **Gone from the map at once.** A removed fart no longer matches the map queries (`is_removed == false`), so the local cache write removes the marker offline. A test on the query side is not possible without the SDK; this is an owner check (Validation). The own-marker query shape stays the one the rules allow.
7. **Rules (emulator).** The author can soft-delete their fart (anonymous and signed-in; PUBLIC with the adult account doc, FOLLOWERS, PRIVATE); another user cannot; a removal combined with a server-owned field is denied; a removed fart can't be changed or un-removed; a hard `delete` is denied. (Most cases exist in `farts.rules.test.ts`; missing ones are added.)
8. **`onFartRemoved` (emulator).**
   - A fart updated to `is_removed = true` loses its `private/location`; the public doc is untouched.
   - An update that doesn't flip `is_removed` (or a fart already removed before) deletes nothing.
   - The same event id runs once; a second run on an already purged fart is harmless.
   - A missing location doc is fine (logged as info, no throw); a delete failure is rethrown so `retry: true` retries.
   - Logs carry the fart id and outcome only, never coordinates.
   - **Race with `onFartCreated`:** a user can log and delete offline, so both batches sync together. `handleFartCreated` on a fart that is already `is_removed` returns quietly (info log `fart_projection_removed`, no write, no error log), also when `onFartRemoved` purged the location first. Emulator tests: removed fart without location → no error log, no write; removed fart with location → no write.
9. `scripts/verify.sh --full` is green, and CI (Android, iOS, backend incl. emulator suites, secret scan) is green.

## Decisions
- **Own-marker tap opens a confirmation dialog, not a sheet.** The full detail sheet is EPIC-01-05. STORY-01-04-01 split this story as "a minimal owner action on the user's own marker". A dialog is the smallest thing that satisfies "destructive actions require confirmation" (DesignSpecification) and is replaced by the sheet's Delete row later. Source: STORY-01-04-01 Decisions, FartDetailSheet.md (confirmation dialog), tie-break "simpler".
- **Soft delete only, by the client.** The rules already allow exactly this update (`is_removed` + `removed_reason = USER_DELETED`) and deny a hard delete, so moderation and sync keep a tombstone. Source: `farts.rules`, DataContracts.md §5.8.
- **The server purges the precise location, not the client.** `private/location` has `update, delete: if false` for clients (ADR-0019, tightened in -01). A purge is therefore a trigger. Source: ADR-0019 §2, tie-break "safer for privacy".
- **Trigger on the fart update, one function per transition.** `onFartRemoved` compares before/after, so only the first flip does work; a redelivery is also guarded by `runOnce`. It is deployed to prod right away because it does real work (the same rule as `onFartCreated`).
- **Purge failure leaves the fart removed.** The public doc is already gone from every list; the trigger retries (`retry: true`). Until it succeeds the precise point still sits in an owner-only doc, which is the state before the delete too. Source: ADR-0019 §4 window, tie-break "simpler".
- **Own detection uses the loaded fart's `authorUid` against the session uid** (as `marker_opened.is_own` already does). The rules, not the client, are authoritative: a crafted delete of someone else's fart is denied.
- **`age_bucket`** is `13_17` or `18_plus` from the active session's age band (a band, never a birth date). Source: Observability.md §11, CLAUDE.md privacy defaults.
- **A rejected delete is reported by the existing `PendingWriteMonitor` snackbar;** the marker then returns, because the cache write is rolled back. No new surface. Source: LocalData.md §3.5.
- **`fart_deleted` counts the user's confirmed intent,** not server acceptance (the write is never awaited). Observability.md §11 is reworded to "delete confirmed by the user". A rejected delete (rare) is still counted, and the snackbar tells the user.
- **No error state in the dialog.** `deleteFart` only fails on blank ids; real failures come back through the snackbar after the dialog is gone, so an error line would be unreachable UI. Source: tie-break "simpler".
- **A missing account doc blocks deleting an own PUBLIC fart.** The update rule runs `validVisibility()`, which needs the 18+ account doc for PUBLIC. It fails closed and can't happen after the age gate (the doc is created first). A rules test pins the allowed case. Not widened.
- **Delete races the create trigger.** `onFartCreated` skips a removed fart quietly instead of logging an error, because an offline log-then-delete is a normal user path (plan review).
- **Privacy and monetization implications.** Nothing new is sent or stored on the device. The delete makes less data exist. No monetization surface changes.

## Plan
**shared `core/domain/fart/FartRepository.kt`**
- `fun deleteFart(uid: String, fartId: String): AppResult<Unit>`: KDoc says never awaited, a blank id is `Failure(ValidationFailed)`.

**firebaseData `firebase/fart/FirestoreFartRepository.kt`**
- `internal fun buildFartDeleteFields(): Map<String, Any?>` → `is_removed to true`, `removed_reason to "USER_DELETED"`, `updated_at to Timestamp.ServerTimestamp`. Unit test pins the exact key set.
- `deleteFart`: validate, `writes.launchWrite("fart.delete") { db.batch().update(fartRef, *fields).commit() }`, return `Success(Unit)`. The author check is the rules' job. (If the GitLive batch API takes `update(ref, vararg Pair)`, use it; otherwise `update(ref, data = mapOf(...))`.)

**shared `feature/map/presentation`**
- `MapState`: `pendingDeleteId: String? = null`.
- `MapAction`: `ConfirmDelete`, `DismissDelete`.
- `MapViewModel` keeps its six dependencies (detekt `LongParameterList` flags seven; no suppression). The write lives in a new `OwnFartDeleter(farts, sessions, analytics)` (presentation), a Koin `factory`, injected into `MapRoute`:
  - `onMarkerTapped`: own → also `pendingDeleteId = id`;
  - `ConfirmDelete`: needs `pendingDeleteId`; clears it and sends `MapEvent.DeleteFart(id)`;
  - `DismissDelete`: clear;
  - `reduce(Loaded)` and the source-reset in `subscribe`: clear `pendingDeleteId` when it is no longer in the list;
  - `OwnFartDeleter.delete(id)`: needs an Active session (uid, `ageBand`); on `Success` tracks `FartDeleted(ageBand)`; on `Failure` tracks nothing; returns whether it was handed off.
- `MapScreen.kt`: `DeleteFartDialog(onConfirm, onDismiss)` (Material 3 `AlertDialog`; "Delete" is the confirm button, "Keep it" the dismiss; 48 dp targets by default), shown while `state.pendingDeleteId != null`; strings `map_delete_title`, `map_delete_body`, `map_delete_confirm`, `map_delete_keep` in the product voice; preview: the dialog.
- `core/observability/Analytics.kt`: `FartDeleted(ageBucket)` → `fart_deleted`, `age_bucket`; `AnalyticsEventTest` +1.

**backend**
- `triggers/fartRemoved.ts`: `handleFartRemoved(db, eventId, fartId, before, after)`: `runOnce(db, triggerKey("onFartRemoved", eventId), …)`; if `after.is_removed === true && before.is_removed !== true` → `db.doc("farts/{id}/private/location").delete()` and `logInfo("fart_location_purged", { fartId })`; else `logInfo("fart_removed_ignored", …)`. Throws propagate (retry).
- `triggers/fartCreated.ts`: after reading the fart, `if (stored.is_removed === true)` → `logInfo("fart_projection_removed", { fartId })` and return, before the location checks.
- `index.ts`: `onFartRemoved = onDocumentUpdated({ document: "farts/{fartId}", region, retry: true }, …)`.
- `.github/workflows/deploy-backend.yml`: add `functions:onFartRemoved` to `PROD_FUNCTIONS`.
- Emulator tests `fartRemoved.test.ts` (acceptance 8) and extra cases in `farts.rules.test.ts` (acceptance 7).
