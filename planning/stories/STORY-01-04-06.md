# STORY-01-04-06: One-time account-link nudge after a guest's first successful log

Status: Done   Epic: EPIC-01-04   Features: UXF-01 (account linking nudge)   ADRs: ADR-0018 §3, ADR-0025, ADR-0022

## Goal
After a guest's first fart is handed off, the app offers once, in a dismissible dialog, to link Google so the fart survives a new phone. It never blocks, never repeats, and never shows for a linked user. Linking reuses `SessionRepository.linkGoogle` (online only; not queued).

## Scope
- **In:**
  - **`PreferencesRepository.consumeAccountLinkNudge(): Boolean`** — true exactly once per user (a boolean `account_link_nudge_shown_at` key written in one atomic edit; the first call returns true, later calls false). User-scoped: added to `USER_SCOPED_KEYS`, so sign-out clears it. A storage error reads as false (never nag on a broken store).
  - **`MainShellViewModel`** gains State (`linkNudge: LinkNudge` = Hidden / Visible / Linking), Actions (`LogHandedOff(queuedOffline)`, `AcceptLinkNudge`, `DismissLinkNudge`) and Events (`LinkNudgeLinked`, `LinkNudgeConflict`, `LinkNudgeFailed(error)`).
  - **Shell UI:** `MainShell` calls `LogHandedOff` from `onFinish`; renders an `AlertDialog` ("Keep this one forever?" / "Link Google" / "Not now"); the new events show snackbars with the existing Profile link strings.
  - **Analytics:** `account_link_prompted` and `account_linked`, both `provider = google` (Observability.md §11).
  - **Docs:** `LocalData.md` (key semantics), `Observability.md`, ROADMAP / STATE; EPIC-01-04 manual test plan (last story of the epic).
- **Out:**
  - Instrumenting the Profile card with `account_linked` (funnel work, EPIC-01-11). The two events here fire only from the nudge.
  - Apple (Phase 2), the Rank link card (EPIC-01-07), the notification prompt and starter-pack offer that also follow the first log (own stories; ADR-0023/0024).
  - Visual polish.

## Acceptance
1. **Shows once.** `LogHandedOff(queuedOffline = false)` for an `Active(ANONYMOUS)` session with an unconsumed nudge sets `Visible` and tracks `account_link_prompted(google)`. The same action again (or after a process restart, i.e. a consumed key) shows nothing.
2. **Not for linked users or other states.** `Active(LINKED)`, `NeedsAgeBand`, `SignedOut` and `Loading` never show it and do not consume the key.
3. **Offline log doesn't spend it.** `queuedOffline = true` shows nothing and does not consume the key (linking needs the network); the next online log can show it.
4. **Accept.** `AcceptLinkNudge` while Visible calls `sessions.linkGoogle()` once (`Linking` blocks a second call). `LINKED` → state Hidden, event `LinkNudgeLinked`, `account_linked(google)`. `CANCELLED` → Hidden, silent. `Failure(Conflict)` → Hidden + `LinkNudgeConflict`; any other failure → Hidden + `LinkNudgeFailed(error)`. The nudge is not re-shown after any outcome (the key is already consumed).
4b. **Session changes.** `AcceptLinkNudge` does nothing if the session is no longer an anonymous Active; a visible nudge hides when the session leaves that state (sign-out, linked elsewhere).
5. **Dismiss.** `DismissLinkNudge` hides it and writes nothing else; never shown again.
6. **Preferences.** `consumeAccountLinkNudge` returns true then false; `clearUserScoped` resets it; a storage error returns false and logs (DataStore test with the existing harness).
7. `scripts/verify.sh --full` green; CI green. Epic test plan `planning/testing/EPIC-01-04.md` exists.

Offline log → no dialog; the next online log shows it. "Link Google" → success snackbar, Profile card gone; a Google account that already has a Fart Map → conflict snackbar.
- Not verified on Windows: iOS build and Google sheet (CI builds iOS; the owner runs the sheet).

## Decisions
- **A dialog on the shell, not a Profile card or sheet.** The shell already owns the post-log hand-off (snackbar, `LoggedFart`), so features don't import each other. An `AlertDialog` is the smallest dismissible surface. Source: ADR-0018 §3 ("never blocks"), UXFlowCatalog.md line 79.
- **Shown once per user, ever (key consumed when the dialog is shown, not on accept).** Source: LocalData.md (`account_link_nudge_shown_at` throttle), UXFlowCatalog "show once". Profile keeps its persistent card.
- **Offline log defers the nudge.** Account linking is online-only and never queued (kotlin-shared rules); ADR-0018 §3 "after the first successful log" is read as the first online one.
- **Key is user-scoped.** A new guest after sign-out is a new user who has not seen it. Source: LocalData.md §5 wipe list ("nudges").
- **Hidden after any link outcome, including failure and conflict.** The user is never nagged twice; the Profile card is the retry path (plan review).
- **The key is spent before the dialog shows.** A process kill in between loses the nudge; never-nag is the safe failure (plan review).
- **The nudge belongs to one guest session.** `AcceptLinkNudge` re-checks the session is still an anonymous Active; a visible dialog hides when the session leaves that state. Tests cover both.
- **`account_linked` is nudge-only for now** (Observability.md says so); Profile card instrumentation is EPIC-01-11.
- **Analytics only from the nudge.** `account_link_prompted` / `account_linked` carry `provider` only (no uid). Profile instrumentation is EPIC-01-11. Privacy: no new data stored or sent.
- **Copy** follows the Profile link strings' voice; no monetization surface.
