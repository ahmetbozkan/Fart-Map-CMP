# EPIC-01-02 manual test plan: session and identity

> Owner's end-of-epic check. Covers STORY-01-02-01 to -04. STORY-01-02-05 (App Check) is deferred and not testable yet. Tick each case per platform; for a failure, open an issue (template at the end) and keep going. The format is in `planning/testing/README.md`.

**What this epic built:**
- the auth entry;
- a guest session;
- the 13+ age gate (only the band is stored);
- a generated public profile;
- Google sign-in;
- linking a guest to Google from the Profile tab, keeping the same uid.

The map, logging and the other tabs are still placeholders.

## Before you start

- [ ] **Dev catalog seeded** (`OwnerTodo.md` A). Without it case 6 fails with `write_rejected`; everything else still works.
- [ ] **Dev configs in place:** the re-downloaded dev configs are in `~/.fartmap/`, then run `bash scripts/inject-config.sh`, on each machine you build on.
- [ ] **Latest `main` pulled.** The `syncAccountProviders` function was deployed to dev by the merge of PR #16; check Actions → "Deploy backend" is green.
- [ ] **Android:**
  - an emulator with a **Google Play** system image (or a phone), with a Google account added in system Settings;
  - install the dev build with `gradlew.bat :androidApp:installDevDebug` (PowerShell) or the `androidApp` run config with variant `devDebug`;
  - the app is named Fart Map Dev.
- [ ] **iOS (on the Mac):** `bash scripts/inject-config.sh`, open `iosApp/iosApp.xcodeproj`, scheme **FartMap Dev**, any iPhone simulator, Run. You sign in to Google inside the sheet.
- [ ] **Two Google accounts.** Account **A** for normal sign-in; account **B**, still unused for Fart Map, for the linking cases.
- [ ] **Firebase console** open on `fart-map-dev`:
  - Authentication → Users;
  - Firestore → `users`.
- [ ] **Logs:**
  - Android Studio Logcat filtered on `System.out` (lines look like `INFO auth/sign_in_google ...`);
  - Xcode's debug console on iOS.
  - Logs must never contain a token, an email, a full uid or a birth year.

**How to reset to a fresh install.** There is no sign-out button yet (EPIC-01-07).
- **Android:** Settings → Apps → Fart Map Dev → Storage → Clear storage, or uninstall.
- **iOS:** delete the app. If it still opens straight on the map, Firebase kept the session in the iOS Keychain, which survives deleting the app. Then use Device → Erase All Content and Settings in the Simulator menu.

**How to make a Google account "new" again:** delete its user in Authentication → Users, and its `users/{uid}` doc (with the `private/account` subdoc) in Firestore.

## Cases

Birth years assume 2026; add one for each later year. Only the year is asked, so the app uses the youngest possible age:
- 2007 or earlier → adult;
- 2008–2012 → teen (13–17);
- 2013 or later → blocked.

### 1. Auth entry
Android ☐ iOS ☐
1. Fresh install, open the app.

**Expected:**
- the title "Fart Map", the tagline, **Continue with Google** and **Continue without account**;
- no Apple button and no "coming soon" text.

### 2. Guest, adult
Android ☐ iOS ☐
1. Tap **Continue without account**. "One quick question" appears.
2. Android only: press Back. The app must **not** go back to the auth entry.
3. Enter `1990`, then tap **Continue**.

**Expected:**
- the app lands on the **Map** tab ("The map is warming up"), with the bottom tabs Map, Social, Rank and Profile;
- **Console:** a new anonymous user under Authentication;
- **Firestore:** `users/{uid}/private/account` has `age_band: "AGE_18_PLUS"`, `is_anonymous: true`, `linked_providers: []`, `is_suspended: false` and timestamps;
- the year 1990 appears nowhere.

### 3. Relaunch keeps the session
Android ☐ iOS ☐
1. After case 2, kill the app and open it again.

**Expected:** straight to the Map, with no auth entry and no age gate. The console shows the same uid and no new user.

### 4. Guest, teen
Android ☐ iOS ☐
1. Reset, then Continue without account → `2010` → Continue.

**Expected:** the Map. The account doc has `age_band: "AGE_13_17"`.

### 5. Under 13 is blocked and stays blocked
Android ☐ iOS ☐
1. Reset, then Continue without account → `2014` → Continue.

**Expected:**
- "Come back when you're 13";
- relaunching shows the same screen, and you can't get back to the age gate;
- **Console:** an anonymous user exists, but **no** `users/{uid}` doc. That's accepted: an orphan Auth user with no data.
- **Known limit:** clearing storage or reinstalling lifts the block (self-declared gate, ContentSafety.md).

### 6. Invalid year, and the edge
Android ☐ iOS ☐
1. Reset, then Continue without account → `3021`.

**Expected:** "That year doesn't look right. Time travel isn't supported yet." The user stays on the gate, and letters can't be typed.

2. Enter `2013`.

**Expected:** blocked. Someone born in 2013 may still be 12, so the app fails safe.

### 7. Public profile is created
Android ☐ iOS ☐ (one run each is enough, for example during case 2)

**Expected:** `users/{uid}` exists with:
- `user_id` = the uid;
- `display_name` like "Wobbly Burrito 42" (adjective, noun, 2-digit number);
- `avatar_id` either `avatar_free_bean` or `avatar_free_cloud`;
- `follower_count: 0`, `following_count: 0`, `is_following_list_public: false`, timestamps.

Logcat/console show **no** `write_rejected`. The Profile tab doesn't display the name yet (EPIC-01-07).

### 8. Offline guest start
Android ☐ iOS ☐
1. Reset, turn on airplane mode (on iOS turn off the Mac's Wi-Fi, since the simulator uses the Mac's network), then tap **Continue without account**.

**Expected:**
- "You're offline. The wind can't carry this one.";
- still on the auth entry;
- no new user in the console.

Turn the network back on; the same tap now works.

### 9. Google sign-in, new account
Android ☐ iOS ☐
1. Reset; make account A "new" (see Before you start).
2. Tap **Continue with Google**. The button shows progress, and a second tap does nothing.
3. Pick account A. The age gate appears; enter `1990`.

**Expected:**
- the Map;
- **Console:** a user with the Google provider and A's email;
- the account doc has `is_anonymous: false`;
- within a few seconds, `linked_providers: ["google"]`: the app asks the server to fill it. If it stays `[]`, relaunch once; it retries on launch. Still `[]` means a bug: look for `account_sync_failed` in the log.

### 10. Google sign-in, returning account
Android ☐ iOS ☐
1. Reset, then **Continue with Google** → account A.

**Expected:** straight to the Map with **no** age gate, and the same uid as in case 9.

### 11. Google sheet cancelled
Android ☐ iOS ☐
1. Reset, tap **Continue with Google**, then dismiss the sheet (Back or swipe down / Cancel).

**Expected:** no message at all, still on the auth entry, and both buttons work again.

### 12. Google sign-in offline
Android ☐ iOS ☐
1. Reset, go offline, then tap **Continue with Google**.

**Expected:**
- an offline message;
- buttons usable again;
- the log shows `auth/google_token google_sign_in_failed error=...` or `auth/sign_in_google auth_failed error=network_unavailable`, with no token, email or uid.

### 13. Link card shows only for guests
Android ☐ iOS ☐
1. As a guest (case 2), open the **Profile** tab.

**Expected:** a card "Keep your legacy safe" with a **Link Google** button.

2. As a Google user (case 10), open Profile.

**Expected:** no card, only the placeholder.

### 14. Link guest → Google
Android ☐ iOS ☐
1. Reset; make account B "new".
2. Guest, adult → Profile → note the uid in the console → **Link Google** → pick B.

**Expected:**
- the snackbar "Linked. Your legacy is safe now.";
- the card disappears;
- you **stay on the Profile tab**: no jump to the Map, no age gate;
- **Console:** the **same uid** now shows the Google provider and B's email;
- within a few seconds the account doc has `is_anonymous: false`, `linked_providers: ["google"]`, and the same `age_band` as before.

### 15. Linked account survives a reinstall
Android ☐ iOS ☐
1. After case 14, reset, then **Continue with Google** → B.

**Expected:** straight to the Map, the same uid as in case 14, and no age gate.

### 16. Link conflict
Android ☐ iOS ☐
1. Reset, start as a guest (adult), then Profile → **Link Google** → pick **A**, which already has its own Fart Map account from case 9.

**Expected:**
- "That Google account already has its own Fart Map. You're still here as a guest.";
- the card stays;
- the console shows the guest uid still anonymous.
- On iOS this is the one path that can't be tested automatically (`Conflict` mapping), so check it carefully.

### 17. Link cancelled / offline
Android ☐ iOS ☐
1. As a guest: **Link Google**, then dismiss the sheet.

**Expected:** nothing shown, and the card is enabled again.

2. Go offline, then tap **Link Google**.

**Expected:** the offline message. Back online, a retry works.

## Not in this epic (don't report as bugs)
- Sign-out, Settings, and editing the name or avatar (EPIC-01-07). A guest whose Google account already has an account can't switch to it yet.
- Sign in with Apple (Phase 2); App Check (STORY-01-02-05, deferred).
- The real map, logging, Social and Rank content (later epics).
- Visual polish (Phase 1 is function first).
- Prod builds: prod Firebase isn't set up (`OwnerTodo.md` C).

## Reporting a bug
Open a GitHub issue titled `EPIC-01-02 case N: <what went wrong>`, labelled `bug`, with:
- the platform and device or simulator;
- the steps;
- expected vs actual;
- a screenshot;
- the matching log lines. Remove any email first; the app's own logs shouldn't contain one.

The next autopilot run fixes open `bug` issues before it starts a new story (autopilot-story §0), or you can ask an agent directly.
