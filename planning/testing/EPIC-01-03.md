# EPIC-01-03 manual test plan: map and markers

> Owner's end-of-epic check. Covers STORY-01-03-01 to -04; nothing is deferred. Tick each case per platform; for a failure, open an issue (template at the end) and keep going. The format is in `planning/testing/README.md`.

**What this epic built:**
- the fuzzed public location projection and a dev fart seed (-01);
- the native map on the Map tab: Google Maps on Android, MapKit on iOS (-02);
- live markers for the visible area, with the Mine / Followers / Everyone filter, loading / empty / error / offline states (-03);
- "center on me": foreground location asked on the first tap, friendly denied / blocked / location-off notices, and later starts open on you (-04).

Logging a fart, the marker detail sheet and the FAB are later epics, so the map only shows seeded farts.

## Before you start

- [ x] **Dev catalog seeded** (`OwnerTodo.md` A), then **dev test farts seeded** (`OwnerTodo.md` D): 30 PUBLIC `seed_fart_*` docs around Istanbul.
- [x ] **Latest `main` pulled.** The merge of PR #24 deployed the two composite indexes: Firebase console → Firestore → Indexes shows both as **Enabled**. While they build, the map shows the error card (case 7).
- [ x] **Dev configs in place:** `bash scripts/inject-config.sh` on each machine you build on.
- [ x] **Android:**
  - `MAPS_API_KEY_DEV` in `androidApp/secrets.properties` (`OwnerTodo.md` D). Blank tiles mean a missing or wrongly restricted key;
  - an emulator with a Google Play image, or a phone; install with `gradlew.bat :androidApp:installDevDebug` (PowerShell) or the `androidApp` run config, variant `devDebug`;
  - the emulator's location: Extended controls (`…`) → Location. Set it somewhere **not** Istanbul (for example Ankara, 39.93, 32.85), so a move is obvious.
- [ x] **iOS (on the Mac):** open `iosApp/iosApp.xcodeproj`, scheme **FartMap Dev**, an iPhone simulator, Run. Simulator location: Features → Location → Custom Location… (for example 39.93, 32.85).
- [x ] **Logs:** Android Studio Logcat filtered on `System.out`; Xcode's debug console on iOS. Logs must never contain coordinates, a uid or a token.

**How to reset to a fresh install** (also resets the location permission):
- **Android:** uninstall Fart Map Dev, or Settings → Apps → Fart Map Dev → Storage → Clear storage **and** Permissions → Location → Don't allow / reset.
- **iOS:** delete the app. If it still opens straight on the map, use Device → Erase All Content and Settings. To reset only location: Settings → General → Transfer or Reset → Reset Location & Privacy.

You need an active session for every case (guest or Google, any adult or teen age band).

## Cases

### 1. The map is the launch screen, with no prompt
Android x iOS ☐
1. Fresh install, start as a guest (adult).

**Expected:**
- the Map tab shows a full-screen native map with tiles, centered on Istanbul at city zoom (a similar zoom on both platforms);
- the filter row **Mine / Followers / Everyone** at the top, **Everyone** selected;
- a round target button at the bottom right;
- **no location permission prompt**;
- pan, pinch-zoom and rotate work.

### 2. Seeded markers
Android x iOS ☐
1. On Everyone, look around Istanbul.

**Expected:** about 30 pins around the center; no pin shows any text. Zoom in and out: pins stay where they are.

### 3. Panning loads other areas
Android x iOS ☐
1. Pan far away (another country), wait, then pan back.

**Expected:** far away: no pins and the card "Suspiciously fresh air" / "Nobody has dropped one here yet. Somebody has to go first." Back in Istanbul: the pins return and the card goes.

### 4. Filters and their memory
Android x iOS ☐
1. Tap **Mine**.

**Expected:** the pins disappear at once (none are yours yet) and the card says "Suspiciously fresh air" / "You haven't left your mark around here. Yet."

2. Tap **Followers**.

**Expected:** no pins; the card "Your crew hasn't arrived" / "Following people is coming soon. Until then, Everyone has plenty of wind."

3. Leave Followers selected, switch to the Profile tab and back, then kill and relaunch the app.

**Expected:** Followers is still selected both times. Tap **Everyone**: the pins come back.

### 5. Marker taps and screen-reader labels
Android x iOS ☐
1. Tap a pin, then tap the same pin again.

**Expected:** no crash, no sheet and no text bubble (the detail sheet is EPIC-01-05).

2. Turn on TalkBack (Android) or VoiceOver (iOS) and move focus onto a pin.

**Expected:** it reads like "A level-3 fart, 2 hours ago". The target button reads "Center the map on me".

### 6. Offline
Android x iOS ☐
1. With pins showing, turn on airplane mode (iOS simulator: turn off the Mac's Wi-Fi), then pan a little within Istanbul.

**Expected:** the cached pins stay and the chip "Offline. Showing what the wind left behind." appears. Pan to a fresh area: nothing breaks. Back online, the chip goes away.

### 7. Error and retry (only if you can trigger it)
Android x iOS ☐
The error card appears when the query fails, for example while the indexes are still building after a deploy.

**Expected:** a card with an error message ("Something went sideways. Try again?" or similar) and **Try again**; tapping it retries. The base map stays visible.

### 8. The camera survives a tab switch
Android x iOS ☐
1. Pan and zoom somewhere specific, switch to Social and back.

**Expected:** the map reopens exactly where you left it, not at Istanbul.

### 9. First "center on me" asks, then centers
Android x iOS ☐
1. Fresh install (the location permission was never asked), start as a guest, set the device location to Ankara.
2. Tap the target button.

**Expected:**
- the OS location prompt appears now, not before;
- Android: the prompt offers **approximate** location only (no "precise" option);
- iOS: the prompt text is "Fart Map uses your location only to center the map on you. Nobody else sees where you are.";
- allow (While using the app / Only this time): the button shows a spinner briefly and the map animates to Ankara at street zoom.

3. Switch tabs and back.

**Expected:** still on Ankara.

### 10. Later starts open on you
Android x iOS ☐
1. After case 9 (permission allowed), kill and relaunch the app.

**Expected:** the map opens on Istanbul for a moment, then moves to Ankara by itself, with **no** prompt. If you start panning before it moves, it doesn't move. **iOS: check this carefully;** it uses a short fresh fix when iOS has no cached one, and only a device run can prove it.

### 11. Denied, then blocked (Android)
Android x
1. Reset, start, tap the target, choose **Don't allow**.

**Expected:** the card "No location, no problem" / "The map works fine without it. Tap the target again whenever you want to find yourself." with **Got it**. The map, pins and filters keep working. **Got it** closes the card.

2. Tap the target again.

**Expected:** Android asks a second time. Choose **Don't allow** again.

3. Tap the target a third time.

**Expected:** no prompt (Android stops asking); the card "Location is switched off for Fart Map" / "Turn it on in Settings to find yourself. Nobody else ever sees where you are." with **Got it** and **Open settings**.

4. Tap **Open settings**.

**Expected:** Android opens Fart Map Dev's App info page. Allow location there, come back, tap the target: the map centers, no prompt.

### 12. Denied (iOS)
iOS ☐
1. Reset, start, tap the target, choose **Don't Allow**.

**Expected:** the "Location is switched off for Fart Map" card with **Open settings** (iOS asks only once). **Open settings** opens the app's page in Settings; allow location there (While Using the App), come back, tap the target: the map centers.

### 13. Location services off
Android x iOS ☐
1. With the app's permission allowed, switch off location for the whole device (Android: quick settings → Location; iOS: Settings → Privacy & Security → Location Services).
2. Tap the target.

**Expected:** the card "Your phone's location is off" / "Switch it on in your phone's settings, then tap the target again." The map keeps working. (On iOS, turning off Location Services can make the app's status read as denied; the "switched off for Fart Map" card is acceptable then.)

### 14. No fix
Android ☐ iOS ☐ (best effort)
If a lookup fails or takes too long (for example an emulator with no location set), the card "Couldn't sniff you out" / "Your location is playing hide and seek. Try again in a moment." appears after up to about 15 seconds, and the log shows a `location/current_location current_location_failed reason=...` line with no coordinates.

### 15. One lookup at a time
Android x iOS ☐
1. Tap the target several times quickly.

**Expected:** one spinner, one move; no stacked prompts or cards.

### 16. No coordinates in logs
Android x iOS ☐
During cases 9–15, scan the log.

**Expected:** no latitude/longitude numbers, uid or token in any line from the app.

## Not in this epic (don't report as bugs)
- Logging a fart, your own markers on Mine, the precise pin for your own farts and the pending-write marker style (EPIC-01-04).
- The marker detail sheet, reactions, report and block (EPIC-01-05).
- The FAB and the overlay app bar (EPIC-01-04 / the design pass); flavor-styled pins and the drop animation (map design pass).
- A blue "you are here" dot (not specified; "center on me" moves the camera only).
- Precise location: Android asks for approximate only in this epic.
- Following people: Followers stays a "coming soon" card until Phase 2 (ADR-0020).
- Analytics (`map_viewed`, `marker_opened`, `location_permission_result`): collection is off in dev builds, so they aren't checked here.
- Visual polish (Phase 1 is function first).

## Reporting a bug
Open a GitHub issue titled `EPIC-01-03 case N: <what went wrong>`, labelled `bug`, with:
- the platform and device or simulator;
- the steps;
- expected vs actual;
- a screenshot;
- the matching log lines. Remove any coordinates or ids first; the app's own logs shouldn't contain them.

The next autopilot run fixes open `bug` issues before it starts a new story (autopilot-story §0), or you can ask an agent directly.
